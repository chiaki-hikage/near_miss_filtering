# experiments/ — 解析結果の索引

`out/` は git の管理外なので、どの結果がどのスクリプトで作られ、今どれを使っているかを git で持つ索引をここに置く。
`out/` のファイルは動かしていない。索引は `out/` を読むだけで作る。

- `index.csv`: 索引の本体 (1 行 = 1 つの結果)
- 作り直し: `uv run python scripts/report/build_experiment_index.py`

## 行の単位

- `out/` 直下のフォルダ 1 つで 1 行。`out/crosswind/` と `out/vibration/` はテーマのまとまりなので、1 段下のフォルダで 1 行
- `out/` 直下のばらのファイルは、最初の `.` より前の名前でまとめて 1 行 (例 `out/chain_ccs_v2.*` は `.breakdown.csv` と `.candidates.csv` の 2 本)

## 列

自動の列は、スクリプトを流すたびに作り直す。

| 列 | 内容 |
|---|---|
| `path` | 結果の場所 |
| `theme` | 名前から決めたテーマ (対応はスクリプトの `THEMES`) |
| `n_files`, `size_mb` | ファイル数と合計の大きさ |
| `mtime_first`, `mtime_last` | 中のファイルの更新日時の最古と最新。**作成日ではない** (コピーや上書きで変わる)。移動先を示す `MOVED.md` などは除いた |
| `has_readme` | フォルダに `README.md` があるか |
| `meta_files` | 実行条件を書いた `*meta*.json` |
| `newer_by_name` | 名前だけで見た後続の版 (`_vN` の N が大きいもの)。中身は比べていない |
| `referenced_by` | `docs/`・`configs/`・`tests/`・`README.md` のうち、この path を書いているファイル |

手で書く列は、スクリプトが書き換えない。新しい行は空欄で足され、`out/` から消えた行は `status` が「out に無い」になって残る。

| 列 | 内容 |
|---|---|
| `producer_script` | 作ったスクリプト |
| `producer_basis` | その根拠。`--out の既定値 (:行)`・文書のコマンド・`scripts/crosswind/path_map.csv` は確かな根拠。**「推定:」で始まるものは出力ファイル名が一致しただけ**で、実行の記録は無い |
| `status` | 下の表のどれか |
| `status_basis` | `status` の根拠 (文書や設定の行) |
| `note` | 補足 |

| `status` | 意味 |
|---|---|
| 採用 | `configs/near_miss_canonical.yaml` が入力に使っている (統一形式の出力の元) |
| 一部採用 | フォルダの一部 (人手ラベルなど) だけを入力に使っている |
| 現行の出力 | 統一形式・API 用サンプルとして今出しているもの |
| 記録 | 結論を README・文書に書いた解析。後の版で置き換わっていない |
| 旧版 | `docs/near_miss_data_inventory.md` で旧版とされたもの、または文書で作り直したと書いてあるもの |
| 旧版・別目的 | 同じ文書で「前段の PoC・別目的」とされたもの |
| 未確認 | 採用か旧版かを決める根拠が見つからなかったもの |
| バックアップ | 整理作業のときに取った写し |

2026-11-11 の初版は 111 行。採用 17、一部採用 2、現行の出力 2、記録 7、旧版 34、旧版・別目的 7、未確認 41、バックアップ 1。

## 手で書く列を直すとき

`index.csv` を直接編集してから、スクリプトを流す。手で書いた値は残り、自動の列だけが新しくなる。
まとめて書き込むときは、`path` と手で書く列を持つ CSV を `--merge-from` で渡す (空欄でない値だけが上書きされる)。
