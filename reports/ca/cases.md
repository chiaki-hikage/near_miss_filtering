# AI 駆動開発の事例

書き方は `reports/ca/README.md`。新しいものを下に足す。

## 2026-10-09〜10 Codex による物理モデルの外部レビュー

- 作業: 路面振動のフルカーモデルを、Codex にレビューさせた。指摘ごとに Claude が判定 (A: 明確な誤り / B: 妥当だが追加検証が必要 / C: 採用しない) を付けて対応した
- 使ったもの: Codex、Claude Code
- 結果: レビュー 3 回分と対応の記録が残っている
- 課題・注意: レビューの記録は `out/` の下にあり、git 管理外。スクリプトで作り直せない記録なので、失われると戻らない
- 根拠: `out/vibration/reviews/` (codex_review_01〜03.md、claude_response_01.md)、`docs/vibration_fullcar_model.md:268`、`docs/vibration_pavement_site19.md:16`

## 2026-10-28 (棚卸しで確認) 路面の目視の記録に AI の暫定判定が混ざっている

- 作業: 振動地点の映像・Street View の目視
- 結果: 目視の記録 (38 地点) に、Claude の暫定判定が含まれている
- 課題・注意: 人の判定と AI の判定が同じ表にあり、区別して使う必要がある。実験索引では「一部目視あり (Claude の暫定判定を含む)」とした
- 根拠: `docs/near_miss_data_inventory.md:145`、`experiments/index.csv` の `out/vibration/locate/`

## 2026-11-10 データセットの取得で、人が AI を止めた

- 作業: 横風の検証のため、BDD100K の GPS/IMU のサンプルを取りにいかせた
- 使ったもの: Claude Code
- 結果: 公式の配布元に接続できなかったため、Claude は Zenodo にある第三者の再配布を見つけ、zip のファイル一覧だけを範囲指定で読んだ (中身は取っていない)。この段階で、人が「正当にダウンロードしてよいか確認して。無理にアクセスしないで」と止めた。再配布はライセンスの表示が公式と違っていた。翌日、公式サイトは復旧していたが、ログインとライセンスへの同意が要るので、AI からは取得しなかった
- 課題・注意: AI は「取れる経路」を探しにいく。取得の前に、配布元が公式か、利用条件を満たすかを確かめる手順が要る (Claude のメモリーに方針として保存した)
- 根拠: 2026-11-10〜11 のセッションの記録

## 2026-11-11 git 管理外のスクリプトをリポジトリに移す

- 作業: `out/` と `data/` の下にあった解析スクリプト 38 本を `scripts/crosswind/` に移した
- 使ったもの: Claude Code
- 結果: 移す前に写しと sha256 を取り、移した後に sha256 の一致、スクリプトを流した出力のバイト単位の一致、全試験を確かめた。どの手順も Claude が組み、人は方針の承認だけをした
- 課題・注意: 作業中に Claude の誤りが 2 回あり、どちらも確認の手順の中で見つかった
  - zsh では変数が単語に分割されないことを見落とし、tar が 3 本のパスを 1 つの名前として扱って失敗した。空の写しができたので、消して作り直した
  - 索引に値を取り込む処理が、既存の補足を上書きした。件数を数え直して気づき、元に戻した
- 根拠: コミット 1f2b926、82a06ec、`docs/project_structure.md` §6

## 2026-11-11 セッションの記録から失われた処理を取り戻す

- 作業: スクリプトが残っていなかった `all_segments_wind.csv` の作り方を、作業したときのセッションの記録 (Claude Code の作業ログ) から探させた
- 使ったもの: Claude Code
- 結果: 取得の URL と日時、処理のコードが見つかった。そのコードを流すと、既存のファイルとバイト単位で一致した
- 課題・注意: その場で実行した処理は、セッションの記録には残るが、リポジトリには残らない。結果を残す処理は、その場でスクリプトとして保存しておく必要がある
- 根拠: `docs/crosswind_wind_data.md`、コミット bb59e83

## 2026-11-11 結果の「採用」と「使われている」を分ける

- 作業: 解析結果 111 件の索引を作らせた
- 使ったもの: Claude Code
- 結果: 最初の版では、設定から参照されているものを「採用」とまとめていた。人の指摘で、利用状況・文書上の区分・検証・正式な採否を別の列に分けた。正式な採否の記録は 0 件だった
- 課題・注意: AI は手がかり (設定から参照されている) から状態 (採用済み) を言い切りがち。根拠の種類ごとに列を分け、推定は「推定:」と書く運用にした
- 根拠: コミット 99e116c、`experiments/README.md`
