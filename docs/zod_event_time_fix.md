## 1. 誤りと修正

**誤り**

- Phase 2 の候補の `t_onset` は「推定開始」(ピークから値が半分を下回るまで戻った時刻)
- `duration_s` は「閾値を超えていた長さ」
- この 2 つを足した [t_onset, t_onset + duration_s] を検出区間として使った。持続型では、推定開始が閾値超過の始まりより最大 21 s 前になる
- 誤った区間を使っていた所
  - Phase 3 の物理の確かめと風の時刻
  - 映像の一覧のカメラとの重なり
  - Phase 2 の `in_camera_sequences` (ピークの前後 2 s で判断していた)

**修正**: 3 つの時刻を別々に持ち、区間はいつも閾値超過区間を使う。定義は `event_time.py` の 1 か所に置いた。

| 時刻 | 列 | 定義 |
|---|---|---|
| 推定開始 | `t_rise` (`t_onset` と同じ値、互換のため残す) | ピークから戻り、\|値\| が 0.5 × \|ピーク\| を下回った直後。高い状態の始まりの推定 |
| 閾値超過区間 | `t_exceed_start`, `t_exceed_end`, `exceed_duration_s` | 検出した run (配列の位置 i0〜i1) の最初のサンプル 〜 最後のサンプル + 0.01 s |
| ピーク | `t_peak` | run の中で \|値\| が最大の時刻 |

- 推定開始は、ふつう閾値超過の始まりより前 (持続型では 1〜21 s 前)
- ただし、1 s 以内のすき間でつないだ run (突発型) では、推定開始がつないだ後ろ側の中にあり、閾値超過の始まりより最大 1.05 s 後になる (67 件のうち 4 件)
- `event_time.event_interval` は、新しい列が無い旧い結果を受け付けない (推定開始 + 長さ で代用しない)

### 1.1 端での打ち切り

| 印 | 意味 | 件数 (重複除外後の 67 件) |
|---|---|---|
| `rise_censored` | 推定開始を戻る途中で、半分を下回る前に OXTS の区間の先頭に達した。本当の始まりは OXTS より前で分からない | 6 |
| `exceed_start_censored` + 理由 | 閾値超過の始まりが、OXTS の区間の先頭か、判定の対象の外 (区間の端 2 s・方向指示器・途切れ・速さ・曲がり) との境 | 10 |

| `camera_relation` | 閾値超過区間とカメラの区間の関係 (窓の中 / 窓の前から続く / 窓の後まで続く / 窓の前 / 窓の後) | 窓の中 31、前から続く 3、後まで続く 2、カメラと重ならない 31 |

**処理の決め**

- Phase 3 の物理の確かめ
  - 閾値超過区間を見る。2 s より短ければ 2 s まで延ばす (従来の規則)
  - 基準 (β・局所のロール) は推定開始の 10〜0.5 s 前 (従来どおり)
  - 推定開始が打ち切りのときは、基準は無い (NaN)
- 風を見る時刻・位置・方位は、閾値超過区間の中央
- 映像
  - 「検出区間の中か外か」は閾値超過区間で判断する
  - 図では、推定開始 (破線)・ピーク (点線)・閾値超過区間 (帯) を分けて描く
  - 注目の候補がカメラの外にあっても一覧に残し、関係を出す

### 1.2 テストで見つけた別の誤り

推定開始の打ち切りの判定を「推定開始の位置 = 区間の先頭」としていた。しかし戻る処理は先頭の 1 つ後で止まるので、打ち切りを見逃していた。戻る処理の側で「半分を下回る前に先頭に達したか」を判断するように直した。

## 5. 別の課題として残すもの (今回は変えていない)

1. 推定開始の定義 (ピークの 50%) は、持続型では高い状態の始まりとして長すぎる (最大 21 s 前)。検出の条件の見直しとして別に扱う
2. 1 s 以内のすき間をつなぐ規則 (`merge_s`) のため、推定開始が閾値超過の始まりより後になる場合がある
3. 重複除外 (`unique_candidates`) と上位の選び方は、従来どおり推定開始 (`t_onset`) で同じ事象をまとめている。閾値超過区間の重なりでまとめるかは、別に決める
4. Phase 3 の観測所の選び (`plan`) は旧い候補の位置で作った。位置の差は数百 m で、半径 50 km の選びには影響しないとみて、計算し直していない
