# ZOD の車両信号の調査 (Sequences mini、横風の外乱推定の準備)

2026-11-12 に、ユーザーが取得した ZOD Sequences mini (`raw_data/zod/`) だけを使って調べた。ネットワークは使っていない (uv も `--offline`)。仕様と取得の手順は `docs/zod.md`、`docs/zod_download.md`。

- コード: `scripts/zod/signal_survey.py` (設定 `configs/zod/signal_survey.yaml`)、`scripts/zod/inspect_signals.py`
- 出力: `out/zod/signal_survey/mini/` (関係・カメラ・モデル・残差・走行条件・図)、`out/zod/signal_inventory/sequences_mini/` (HDF5 の全列・周期)
- 実行: `uv run --offline --extra viz --with "zod==0.8.0" --with "dataclass-wizard==0.39.1" python scripts/zod/signal_survey.py --root raw_data/zod --version mini` (プロジェクトの環境に zod を上乗せする。`pyproject.toml`・`uv.lock` は変わらないことを md5 で確かめた)

**mini は 2 シーケンスだけ**なので、ここでの数値は 2 台・2 走行の例で、一般化はできない。「確認」はデータで確かめたこと、「推定」はそうでないことを指す。

## 3. 時刻の同期

| 組 | 方法 | 結果 |
|---|---|---|
| 車両データ ⇔ OXTS | 同じ量の相互相関 (車速、横加速度、ロール角速度) | **ずれ 0〜0.03 s** (車速は 0 / −0.01 s、横加速度は 0 / −0.03 s)。同じ時計とみてよい |
| 舵角 → ヨーレート | 相互相関 | ヨーレートが舵角より 0.06 s 遅れる (車の応答の遅れとして自然) |
| 車両データの時刻 ⇔ 衛星の UTC (秒まで) | 差 | 0.72〜1.67 s。UTC が秒単位で切り捨てられているので、0〜1 s の幅は当然。それを超える分 (受信の遅れなど) は分からない。同期には使わない |
| カメラ ⇔ OXTS | 3 フレーム (0.3 s) 離れた画像の、地平線のまわりの帯の横のずれ (位相相関、中央値フィルタ) と、同じ区間の OXTS の方位の変化を、時刻をずらして比べる (`camera_sync.csv`、図 `plots/<id>_camera_sync.png`) | 000000 (向きの変化が大きい): ずれ 0 の相関 0.67、最大 0.69。**最大の位置は −1.0〜−0.14 s の幅でなだらかで、決まらない**。画面のずれの大きさは fx の 1.11 倍。000002 (ほぼ直進): 相関 0.22 で判定できない |

カメラについて言えること:
- 形 (曲がる区間) は OXTS と合っている (図)。±1 s を超える大きなずれは見えない
- 0.1 s の精度での確認は、この方法ではできなかった。近くの木・トラックの動き (視差) と、位相相関の外れが残る
- 横風の解析では、カメラは確認用 (CLAUDE.md の方針) で、0.5 s 程度の対応で足りる。より正確に要るなら、ライダーのスキャンの時刻、または車線の位置と OXTS の横の位置で確かめる (未実施)

## 4. 外乱推定ができるか

### 4.1 OXTS がある 50 s: 単軌道モデルのヨー残差

comma2k19 の Civic と同じ式 (`docs/crosswind_civic_feasibility.md` (4.1)–(4.3)) を、シーケンスごとに当てはめた: δsw = a·(r/v) + b·(v·r) + c。r は OXTS のヨーレート (左回りを正にそろえた)、v は OXTS の速さ、δsw は車両データの舵角。前半で当てはめて後半で測り、逆も行った (2 分割の交差検証)。

| | 000000 (quebec) | 000002 (romeo) | 参考: Civic (comma2k19) |
|---|---|---|---|
| 舵角の R² | 0.994 | 0.949 | 0.988 |
| a + b·v² (見かけのギヤ比 × ホイールベース) | 58.4 m (64 km/h) | 58.0 m (48 km/h) | 48〜76 m |
| c (舵角の中立のずれ) | 1.6 deg | **3.7 deg** | −0.20 deg |
| **ヨー残差の標準偏差 (交差検証)** | **0.24 deg/s** | **0.15 deg/s** | 0.244 deg/s |
| ヨー残差の \|p99\| | 0.59 deg/s | 0.51 deg/s | 0.73 deg/s |

- 速度の幅が狭い (60〜67、42〜54 km/h) ので、a と b を別々には決められない (a + b·v² だけが決まる)。full なら、同じ車両の多くのシーケンスをまとめて決められる見込み
- 000002 の c ≈ 4 deg は、ヨーがほぼ 0 のときの舵角の中央値 (4.2 deg) とも合う。車両 (romeo) の舵角センサのずれとみられる (推定)。車両ごとに c を当てはめる必要がある
- 図: `plots/<id>_sequence.png` (速さ・舵角・ヨーレートの実測と予測・横加速度・操舵トルク)

### 4.2 走行全体: 舵角と横加速度

ヨーレートは 50 s しかないので、走行全体では車両データの横加速度で同じ形の式を当てはめた: δsw = a·(ay/v²) + b·ay + c。

| | 000000 | 000002 |
|---|---|---|
| 舵角の R² | 0.88 | 0.90 |
| 使った点 (10 m/s 超・横躍度 0.5 m/s³ 未満・\|ay\| 0.3 m/s² 超・方向指示器なし) | 10,169 (37〜117 km/h) | 22,477 (36〜147 km/h) |
| 高速 (80 km/h 超)・直進 (\|δsw − c\| < 3 deg) の時間 | 15.2 分 | 75.8 分 |
| その区間の横加速度の残差 (0.2〜2 Hz) の標準偏差 | 0.060 m/s² | 0.090 m/s² |
| 同 \|p99\| | 0.17 m/s² | 0.34 m/s² |
| 同 操舵トルクの標準偏差 | 0.76 N·m | 0.64 N·m |

- **横加速度には路面の横の傾き (重力の成分) が入る。** 000002 の OXTS の区間では、ヨーレートはほぼ 0 なのに横加速度が −0.30 m/s² (ロール −2.1°) あった。横加速度だけでは、カーブを曲がる分と傾きの分を分けられない。そのため、走行全体の a, b, c は見かけの値で、残差は**ゆっくりした変化を除いた帯域 (0.2〜2 Hz) だけ**を見る
- 000002 の 10:20〜10:24 UTC (130〜146 km/h) に、帯域の残差が ±0.7〜1.2 m/s² の区間が続く (`top_events.csv`)。方向指示器は多くが消灯。**カメラはこの時刻に無いので、原因 (路面・追い越し・風など) は確かめられない。横風とは判断していない**
- 帯域の残差は速度が高いほど大きい (図 `plots/000002_drive.png`)。comma の検討の「1 窓の雑音 0.05 m/s²」とは定義が違うので、直接は比べない

### 4.3 判断

**外乱推定はできる見込み**。comma2k19 より有利な点と、限られる点:

有利な点
- 舵角・操舵トルク・方向指示器・高精度のヨーレートと横速度 (横滑り角そのもの) がそろい、時刻が合っている
- ヨー残差の雑音が Civic と同じくらい (0.15〜0.24 deg/s)
- **UTC の時刻と位置**があり、気象の観測と照合できる (PhysicalAI-AV には無かった)
- 操舵トルクで、当て舵 (運転者が外乱に逆らう操作) を直接見られる見込み

限られる点
- **ヨーレート (OXTS) とカメラは 1 シーケンスあたり 50 s と 20 s だけ**。走行全体には舵角・トルク・横加速度・車速と 1 Hz の位置しか無い
- 走行全体の横加速度は、路面の傾きと分けられない (帯域を通して見る)
- 舵角の中立のずれが車両ごとに違う (000002 で約 4 deg)
- 車両データの横速度は使えない (OXTS と合わない)、ピッチ角速度は 0
