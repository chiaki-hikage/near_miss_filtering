# Toyota RAV4 (comma2k19) 信号の検証記録

対象: dongle `b0c9d2329ad1606b` (comma2k19 Chunk 1-2, Toyota RAV4)
検証セグメント: `Example_1/b0c9d2329ad1606b|2018-08-02--08-34-47/40`
ビット定義の出典: `opendbc/dbc/generator/toyota/_toyota_2017.dbc`

DBC のビット定義は「そのIDに信号が入っている」ことしか保証しない。
符号の向きとスケールは車種・年式で食い違うため、ここに実測で確かめた結果を残す。
未検証の信号は検証済みの信号と同じようには使わない。

## 1. 検証済み

### ACCEL_X / ACCEL_Y (CAN ID 36 = 0x024 KINEMATICS) — 符号が反転している

`processed_log/CAN/speed` (README で m/s と明記) を 20 Hz の一様グリッドへ
再サンプルし、0.55 秒平滑をかけてから微分した値を基準とした。

```
a_ref  範囲 [-1.23, +1.70] m/s^2
ACCEL_X 範囲 [-1.39, +0.78] m/s^2
相関 r = -0.843
回帰   ACCEL_X = -0.779 * a_ref - 0.036
最大減速点 (a_ref = -1.23) で ACCEL_X = +0.72
最大加速点 (a_ref = +1.70) で ACCEL_X = -1.10
```

**結論: ACCEL_X は減速で正。進行方向を正とするには -1 を掛ける。**

ACCEL_Y も同じ向きに反転している。YAW_RATE との相関が r = -0.810 で、
旋回方向と横加速度の符号が逆になっているため。
**結論: ACCEL_Y にも -1 を掛ける。**

回帰の傾き 0.779 が 1 に届かないのは、基準側 (a_ref) に量子化ノイズが残り
回帰係数が 0 側へ引かれるため (errors-in-variables) と解釈している。
スケールファクタ 0.03589 自体が正しいかは**確定していない**。
このため縦加速度の主系列には ACCEL_X ではなく車速微分を使い、
ACCEL_X は突き合わせ用の副系列として扱う。

### YAW_RATE (CAN ID 36) — 符号もスケールも妥当

符号は舵角との突き合わせで確認した。

```
corr(YAW_RATE, steering_angle)  = +0.897
corr(YAW_RATE, 自転車モデル推定) = +0.908
```

スケールは `global_pose` の ECEF 速度から求めた方位角変化率を基準に検証した。
方位角は北から時計回りなので、車両規約 (左旋回が正) に直すため符号を反転して比較する。
Chunk_1 から間引いた 62 セグメントのうち、自車速 5 m/s 超・基準の標準偏差 0.4 deg/s 超で
相関 0.9 を超えた 43 本を採用。

```
相関   中央値 +0.983
回帰係数 中央値 0.988   四分位 [0.978, 0.997]
```

**結論: スケールファクタ 0.244 は正しい。符号も補正不要。**

これにより `ay_kin = 車速 × YAW_RATE` が単位の確かな横加速度 [m/s^2] になる。
本プロジェクトはこれを横方向の主系列として使う。

### ACCEL_Y のスケール — 確定できない

同じ基準で `ACCEL_Y` のスケールも見た (基準は 車速 × 基準ヨーレート [m/s^2])。

```
相関   中央値 +0.952
回帰係数 中央値 0.678   四分位 [0.623, 0.726]
```

基準の 0.68 倍しか出ていない。ただしこれは**スケールファクタの誤りとは断定できない**。
横加速度計は路面のカント (片勾配) の分だけ小さく読む。280 号線の曲線には
片勾配が付いており、その寄与と信号のスケール誤差を、この比較では分離できない。

**結論: ACCEL_Y のスケールは未確定のまま。** 横加速度は `ay_kin` を使い、
`ACCEL_Y` は `ay_can_mps2` として並置するに留める。

### radar の相対速度 — 負が接近

`processed_log/CAN/radar` の各トラック (address 528-541) を `new_track` で区切り、
前方距離の時間変化率と列 2 (相対速度) を比較した。

```
corr(d(距離)/dt, v_rel) = +0.998
回帰係数                = +0.988   (n = 45 トラックセグメント)
```
**結論: `v_rel = d(距離)/dt`。`v_rel < 0` が接近。TTC = 距離 / (-v_rel)。**

### タイムスタンプのジッタ — 生の時刻で微分してはいけない

`raw_can` / `processed_log` とも時刻は単調増加だが、間隔が大きく揺れる。

```
CAN/speed        dt min/med/max = 0.000177 / 0.011211 / 0.026461 s
raw_can 0x0AA    dt min/med/max = 0.000177 / 0.011211 / 0.026461 s
```

輪速の分解能は 0.01 km/h。dt = 0.000177 s のところで 1 LSB 変化すると
見かけの加速度が 15 m/s^2 を超える。実際、生の時刻のまま微分すると
輪速由来の加速度が +180 m/s^2 まで飛んだ。
**一様グリッドへ再サンプルしてから微分する。これは必須の前処理。**

### 同一アドレスが複数バスに流れる — バスを指定せずに復号してはいけない

`raw_can/src` は下位ビットがバス番号、0x80 が送信フラグ。
受信フレームだけを見ても、**同じアドレスがバス 0 とバス 1 に別の内容で流れている**
ことがある。1 セグメントの全アドレスを走査した結果、衝突していたのは 5 件。

```
0x223 (547)  bus0 2488 / bus1 1200
0x224 (548)  bus0 2487 / bus1 1200   ← BRAKE_MODULE。本プロジェクトで使用
0x228 (552)  bus0 2487 / bus1 1200
0x232 (562)  bus0 1658 / bus1 1200
0x3D3 (979)  bus0  114 / bus1  600
```

0x224 の中身は次のとおりで、別のメッセージであることが一目で分かる。

```
bus0   20 00 00 00 00 E3 00 08    byte0 のユニークは 2 種 (0x00 / 0x20)
bus1   BE 00 00 00 00 00 00 EC    byte0 のユニークは 256 種 (ローリングカウンタ)
```

バスを指定せずに復号するとカウンタの bit5 が混ざり、`BRAKE_PRESSED` が
59 秒間に 149 回チャタリングしていた。**車種設定では全信号に `bus` を明記し、
送信フレームは常に除外する。**

本プロジェクトで使う他のアドレスはいずれもバス 0 単独なので影響はない。

```
0x024 KINEMATICS    bus0 のみ
0x0AA WHEEL_SPEEDS  bus0 のみ
0x0B4 SPEED         bus0 のみ
0x320 VSC1S07       bus0 のみ
```

### BRAKE_PRESSED (CAN ID 548 = 0x224, bit 5, bus 0) — バス指定後は使える

バスを指定してから、縦加速度との突き合わせで挙動を確認した。

| | バス指定なし | バス 0 のみ |
|---|---|---|
| 59 秒間の切替回数 | 149 | **13** |
| 加速中 (ax > +0.5) に 1 の割合 | 13.9% | **0.0%** |
| 減速中 (ax < −0.5) に 1 の割合 | 77.4% | 86.0% |
| 縦加速度との相関 | −0.543 | **−0.770** |

**結論: 制動の有無を示すフラグとして使える。** 加速中の誤りが 0% になった。

### IMU との突き合わせ — CAN 側の裏取り

IMU は特徴量には使わないが、独立系統として CAN の値を裏取りできる。
軸は `[forward, right, down]`。車載機の取付角のぶんだけ重力が forward に漏れる。

```
IMU forward   vs 車速微分   r = +0.981   回帰係数 +1.047   直流 −0.385 m/s^2
IMU gyro down vs YAW_RATE   r = −0.999   回帰係数 −0.965
```

gyro が逆符号になるのは down 軸まわりの回転だからで、左旋回を正とする
車両規約とは定義上逆になる。いずれも CAN 側の符号・スケールと矛盾しない。

### 線形単軌道モデル — ステアリングギヤ比とアンダーステア勾配

舵角からヨーレートを予測できれば、実測との差で異常挙動を見つけられる。
そのために必要なギヤ比は未検証だったので、実測から求めた。

定常旋回で成り立つ関係を、小さなヨーレートで割らない形に直して当てはめる。

```
δsw = SR·L·(r/v) + SR·Kus·(v·r) + δoffset
```

Chunk_1 の定常旋回 (車速 10 m/s 超、|横躍度| < 0.5、|ヨーレート| > 1 deg/s) 36,818 点。

```
ステアリングギヤ比      SR       = 16.75
アンダーステア勾配      Kus      = 0.00235 rad·s²/m  (前輪換算で約 1.3 deg/g)
舵角センサのゼロ点ずれ  δoffset  = +0.911 deg
決定係数                R²       = 0.973
```

**結論: モデルは成立する。** ギヤ比 16.75 は RAV4 として妥当な範囲。
ゼロ点ずれ 0.9 度も、アライメントやセンサ較正のずれとして説明がつく。

見かけのギヤ比 (Kus を無視して求めた値) は速度とともに 17.6 → 32.3 と
単調に増える。アンダーステア特性そのもので、モデルの形が合っていることの裏付けになる。

#### 残差の性質

```
残差 (実測 − 予測)   中央値 -0.054 deg/s   標準偏差 0.341 deg/s
|残差|               p99 1.00   p99.9 1.47   最大 2.91 deg/s
```

|残差| > 1.5 deg/s の点は、|横躍度| の中央値が 1.84 (全体は 0.28) で、
**大半が操舵の立ち上がりによるもの**。定常状態のモデルなのでヨー応答の
遅れを表現できず、過渡で差が出る。定常に絞ると |残差| > 1.5 は
全サンプルの 0.011% しかない。

**Chunk_1 の 3.1 時間、車両は一貫して線形領域にあった。** 滑りや
グリップの喪失を示す残差は現れていない。

### ABS の作動 — 判定できる情報が無い

`FABS` (0x320 bit 2) を ABS 作動フラグとして復号しているが、Chunk_1 の
3.1 時間で 1 度も立たない。ビットが誤っているのか、本当に作動していないのかを
切り分けた。

**結論: 本当に作動していない。** ABS が作動しうる状況が無かった。

```
最大減速度              -4.44 m/s² = 0.45 g
乾燥路のタイヤ限界      概ね 0.8〜1.0 g
強制動時 (ax<-3.0) の前後輪速度差   中央値 0.015 m/s
通常走行時の前後輪速度差            中央値 0.044 m/s
```

強い制動をかけている間の前後輪の速度差は、通常走行時よりむしろ小さい。
車輪のロックもスリップも起きていない。**このデータでは `FABS` の正しさを
確かめようがない。**

関連するメッセージも中身が無い。

```
0x3B7 ESP_CONTROL   199 フレーム   64 ビットすべて固定値
0x420 VSC1S08        60 フレーム   64 ビットすべて固定値
```

ビット定義を入手しても読む中身が無い。**VSC / TC の介入もこのデータには存在しない。**

### DECEL_FLAG (0x320 = VSC1S07, start_bit 63, bus 0) — 強い減速で立つ

ABS を探す過程で、全 64 ビットを走査して見つけた。強い制動を含む 5 セグメントで
「制動中だけ立つビット」を探したところ、5/5 で該当したのはこれ 1 つだけだった
(他の候補はレーダのトラックビットで、制動中に交通状況が変わることによる偶然の一致)。

Chunk_1 全体 224,007 サンプルでの点灯率は、縦加速度でほぼ決まる。

| 縦加速度 | 点灯率 | n |
|---|---|---|
| −3.5 〜 −3.0 m/s² | 100.0% | 78 |
| −3.0 〜 −2.5 | 95.9% | 271 |
| −2.5 〜 −2.0 | 54.5% | 679 |
| −2.0 〜 −1.5 | 16.3% | 2,049 |
| −1.5 〜 −1.0 | 0.3% | 4,628 |
| −1.0 より弱い | 0.0% | 216,278 |

50% を切る点は約 −2.4 m/s²。**−1.0 m/s² より弱い減速では 1 度も立たない。**
`BRAKE_PRESSED` が 12.9% の時間で 1 なのに対し、これは 0.50% しかない。
単なるブレーキスイッチではない。

**ABS ではない。** ABS は車輪のスリップで作動するが、これは減速度だけで決まる。
緊急制動表示灯 (ESS) やブレーキアシストの作動が候補だが、DBC で確認していない。
**挙動は検証済み、信号名の意味は未確定**として扱う。

用途としては、こちらが車速から導いた `ax_mps2` を車両側から裏付ける independent な
確認になる。Chunk_1 では `hard_brake` を含む候補 11 件すべてでこのフラグが立っていた。

### BRKON (0x320, start_bit 8) — ビット位置が誤り

Chunk_1 全体で常に 0。無効にしてある。制動の有無は `BRAKE_PRESSED` を使う。

### 診断通信 (UDS / OBD-II) — 存在しない

1 セグメントの全 address (165 種) を走査した結果、診断応答レンジ `0x7xx` は 0 件。
grey panda がバスを傍受しているだけで、スキャンツールが接続されていないため。
「診断情報」に相当するものとして使えるのは以下:

- 車両側の作動フラグ: `0x320 VSC1S07` の FABS (ABS 作動) など
- openpilot の送信フレーム: `raw_can/src >= 128` (下記)
- `raw_log.bz2` の capnp ログ (今回は CAN のみで進めるため対象外)

### openpilot の介入 — src で判別できる

`raw_can/src` は 0, 1, 128, 129 を取る。128 以上がデバイス送信フレーム。
検証セグメントでは `0x2E4 STEERING_LKA` が 100 Hz、`0x343 ACC_CONTROL` が 43 Hz で
src = 128 として観測された。**この区間の操舵と車間制御は openpilot が出している。**
人間の運転挙動として解釈できないため、検出結果には必ず属性として付ける。

## 2. 未検証 / 使用しない

### BRAKE_PRESSURE (CAN ID 548 = 0x224, start_bit 43, length 12) — ビット位置が誤り

当初は「非ゼロが 17%、1 サンプルおきに 0 と 1028 を往復する」という症状だったが、
その大半はバス衝突が原因だった。バス 0 に絞ると往復は 1243 回から 61 回に減る。

それでも値は使えない。バス 0 に絞った後の値は**すべて 256 の倍数**
(768, 1536, 2560, 3584, 1280, 2048, 3328, …) になる。start_bit 43 / length 12 は
byte5 の下位 4 ビットと byte6 にまたがるが、bus0 のフレームでは byte6 が常に 0 で、
取り出しているのは byte5 の下位ニブルだけ。byte5 はカウンタなので、
これは制動入力ではない。

**結論: ビット位置が誤り。無効のまま据え置く**
(`configs/vehicles/toyota_rav4.yaml` の `enabled: false`)。
制動の有無は `BRAKE_PRESSED` で代替できる。踏力に相当する量は現状取れない。

### ASLP (CAN ID 800, start_bit 23) — 勾配だが要スケール補正

global_pose の ECEF 速度から求めた実勾配と r = +0.762、回帰 ASLP = 0.577 * 勾配[deg]。
勾配としては使えるが 1 deg 刻みで量子化が粗い。
今回は CAN のみ・ヒヤリハット抽出が目的のため使用しない
(縦加速度の勾配補正を行う場合に再検討する)。

### ESP_CONTROL (CAN ID 951 = 0x3B7) — ビット定義未取得

TC_DISABLED / VSC_DISABLED が入っているとされるが、ビット位置を確認していない。
推測で復号しない。必要になった時点で DBC を当てて検証する。
メッセージ自体はセグメント内に 199 件存在する。
