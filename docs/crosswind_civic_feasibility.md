# comma2k19 の Civic で横風の影響を検出できるか

comma2k19 の Chunk 3〜10（Honda Civic）で、強風の時間帯の走行から横風の影響を拾えるかを確かめた。
期間は 2026-11-05〜06。2026-11-09 に、イベント単位の追加解析（7 章）と時刻の丸めの訂正（8 章）を追記した。

## 0. 結論

**今のデータでは、横風の影響は検出できなかった。** ただし、影響がないとも言えない。

- 指標は 2 つ試した。どちらも、強風の時間帯と弱風の時間帯で差が出なかった。
  - **ヨー残差**：舵角から単軌道モデルで予測したヨーレートと、実測との差（4.4）。
  - **横滑り角 β**：進路と車体の向きの差（6.1）。
- β の分解能は、風 1 m/s あたり ±0.01 deg まで出た。それでも、物理から見込まれる効果（風 1 m/s あたり −0.004 deg 程度）を見分けるには足りない。
- 強風の時間帯はすでに全部使っている。comma2k19 の中で、データを増やして精度を上げることはできない。
- **イベント単位で探しても、自動運転モデルの追加学習に使える高信頼の強風ヒヤリハット候補は 1 件も見つからなかった（7 章）。** 拾えた山は、どれもカーブを曲がることによる横滑り、単軌道モデルの過渡のずれ、計算上の段差のどれかだった。突風を受け、横外乱が出て、その後に当て舵をする、という形のものは無かった。
- 「横方向の外乱を広く拾い、原因を横風に絞る」という二段の設計は、そのまま使える。検証には、車に風速計の付いたデータか、強風の時間帯が桁違いに多いデータが要る。

途中で得られた、ほかにも使える結果は次のとおり。

- Civic の IMU のジャイロには、走行中に増えていくずれが残る。補正のやり方は確立した（3.3）。
- Civic の単軌道モデルを当てはめた。残差の標準偏差は 0.244 deg/s で、RAV4（0.341 deg/s）より小さい（4.3）。設定は `configs/crosswind/honda_civic.yaml` に置いた。
- global_pose の `frame_orientations` の向きの解釈を、データで確定した（6.2）。

5 章と 6 章の数値は、時刻を丸めた時系列から出したものである。全精度で計算し直しても結論は変わらないが、一部の数値は変わった（8 章）。

## 3. 記号と座標の約束

3〜6 章で使う記号をまとめる。角度は式の中ではラジアン、表では deg で示す。

| 記号 | 意味 | 単位 | 元のデータ |
|---|---|---|---|
| v | 車速 | m/s | `processed_log/CAN/speed`（0.25 s の移動平均） |
| δsw | ハンドルの回転角（舵角）。左が正 | rad | `processed_log/CAN/steering_angle`（0.15 s の移動平均） |
| r | ヨーレート（車体が鉛直軸まわりに回る速さ）。左回りが正 | rad/s | IMU のジャイロ（3.2 で作る） |
| ψ̇ | 進路の向きの変化率。右回りが正 | rad/s | global_pose の速度（3.1） |
| a_y | 横加速度。ここでは a_y = v·r で求める | m/s² | |
| L | ホイールベース（前輪軸と後輪軸の距離） | m | |
| SR | ステアリングギヤ比。前輪の切れ角 = δsw / SR | − | 当てはめる |
| Kus | アンダーステア勾配（4.1） | rad·s²/m | 当てはめる |
| δoffset | 舵角センサのゼロ点のずれ（まっすぐ走るときの δsw） | rad | 当てはめる |
| W、D | 風速、風が吹いてくる方位（北から時計回り） | m/s、deg | SFO の観測 |
| H | 車の進路の方位（北から時計回り） | deg | global_pose の速度 |
| β | 横滑り角。進路と車体の向きの差。左が正 | rad | global_pose（6.1） |

すべての信号は 20 Hz の共通の時刻にそろえた。ドライブの中では時刻が続いているので、セグメントをまたいで扱える。

### 3.1 進路の向きとその変化率

global_pose の `frame_velocities` は、カメラの速度を ECEF 座標（地球中心の直交座標）で表したものである。これをセグメントの中央の位置での東・北・上の座標（ENU）に回し、東向きの成分を v_E、北向きの成分を v_N とする。

    H = atan2(v_E, v_N)            進路の方位。北から時計回り
    ψ̇ = dH/dt                     1 Hz の低域通過をかけてから微分。右回りが正

### 3.2 ジャイロからヨーレートを作る

ジャイロの軸はスマートフォン型の端末の向きで、車体とは少し傾いている。

1. **取付の傾きを戻す**：ドライブの加速度の平均が真下を向くように回す。これは既存の振動の解析と同じ処理である。回した後の z 軸は下向きで、z 軸まわりの角速度 g_z は右回りが正になる（2 章で確認）。
2. **ずれを推定する**：3.3 のやり方で、時刻ごとのずれ b(t) を推定する。
3. **ヨーレートにする**：左回りを正にするため、符号を反転する。

       r(t) = −( g_z(t) − b(t) )

### 3.3 ジャイロのずれの推定

`processed_log/IMU/gyro` は、「補正前の値 − 端末が推定したバイアス（`gyro_bias`）」になっている。この端末のバイアスは停車中にしか更新されないので、走行中はずれが残って増えていく。

- **ずれの大きさ**：ドライブの間で −3.6〜+1.1 deg/s。2018-07-10 のドライブでは、30 分で 0.1 から 1.66 deg/s まで増えた。温度によるドリフトと考えられる。

ずれを推定する考え方は次のとおり。g_z も ψ̇ も、右回りを正とした回転の速さである。ずれが無ければ、2 つは長い時間でならすと一致するはずだ。そこで、その差の 60 s の移動中央値をずれとみなす。

    b(t) = 中央値{ e(t') : |t' − t| ≤ 30 s }

    e(t') = g_z(t') − ψ̇(t')     走行中（CAN の車速と GNSS の速さがともに 5 m/s 超）
          = g_z(t')              停車中（CAN の車速 0.05 m/s 未満、GNSS の速さ 0.1 m/s 未満）。
                                 真の回転は 0 なので、g_z がそのままずれ

走行中の差を取るときは、ψ̇ と時間の細かさをそろえるため、g_z にも 1 Hz の低域通過をかけた。

- 平均ではなく中央値を使う理由：ψ̇ が不正確な低速の区間や、突風で横滑り角が一時的に変わる区間の影響を受けにくくするため。
- 推定に足る標本が 60 s の中に無いとき（全体の 0.8%）は、前後の推定値から時間で補間した。
- **推定の精度**：停車区間 62 個で照合した。停車の前後 30 s の走行中だけから推定した値と、停車中に実測したずれとの差は、中央値 +0.014 deg/s、ばらつき（ロバストな σ）0.062 deg/s だった。
- **補正しないと**：4 章のモデルの残差の標準偏差は 1.28 deg/s、舵角の R² は 0.68 に落ちる。
- **横風の影響まで消さないか**：ψ̇ は進路の実際の回転である。そのため、横風で車体が回れば g_z と ψ̇ の両方に現れ、差 e には残らない。横滑り角が一定のまま変わらなければ、車体と進路は同じ速さで回るので、やはり e に影響しない。

## 4. 単軌道モデルの当てはめ

### 4.1 モデルの式と各項の意味

単軌道モデルは、左右の車輪を 1 つにまとめ、前輪 1 つ・後輪 1 つの二輪車として扱う、車両運動のいちばん簡単なモデルである。一定の半径で曲がっている定常の状態では、前輪の切れ角 δ と旋回の関係が次のように書ける。

    δ = L / R + Kus·a_y

- **L / R（幾何の項）**：半径 R の円を、ホイールベース L の車がタイヤを横に滑らせずに回るのに要る切れ角。
- **Kus·a_y（アンダーステアの項）**：タイヤは横向きの力を出すときに少し横に滑る。乗用車は、前輪のほうが後輪より多く滑るように作られている（アンダーステア）。そのため、横加速度 a_y が大きいほど、余分に切る必要がある。その割合が Kus である。

定常の旋回では R = v / r、a_y = v·r なので、次のように書き直せる。

    δ = L·(r / v) + Kus·(v·r)

ハンドルの角度 δsw は、切れ角をギヤ比 SR 倍したものに、センサのゼロ点のずれを足したものである。

    δsw = SR·δ + δoffset
        = SR·L·(r/v) + SR·Kus·(v·r) + δoffset          … (4.1)

### 4.2 当てはめ方

(4.1) は、未知数 a = SR·L、b = SR·Kus、c = δoffset について線形である。

    δsw = a·x₁ + b·x₂ + c       x₁ = r / v、x₂ = v·r

そこで、各時刻の (v, r, δsw) を並べて、最小二乗で a、b、c を求めた。式も条件も RAV4（`docs/signals_rav4.md`）と同じである。

- **前処理**：パイプラインに合わせた。20 Hz にそろえ、車速は 0.25 s、舵角とジャイロは 0.15 s の移動平均をかけた。
- **条件**：(4.1) は定常の旋回の式なので、それに近い時刻だけを使った。
  - 車速 10 m/s 超
  - 横躍度（a_y の時間微分）の絶対値 0.5 m/s³ 未満：操舵を切り始めたばかりの過渡を除くため
  - ヨーレートの絶対値 1 deg/s 超：直進では x₁、x₂ がほぼ 0 になり、a と b が決まらないため
- **使ったデータ**：弱風の 150 セグメントだけ（41,536 点）。風の影響をパラメータに取り込まないため。

### 4.3 結果

| | Civic | RAV4 |
|---|---|---|
| a = SR·L | 41.84 m | 44.56 m |
| b = SR·Kus | 0.0238 s² | 0.0394 s² |
| c = δoffset | −0.20 deg | +0.91 deg |
| 舵角の R² | 0.988 | 0.973 |
| ヨー残差（4.4）の標準偏差 | 0.244 deg/s（交差検証） | 0.341 deg/s |
| ヨー残差の \|p99\| / \|p99.9\| / 最大 | 0.73 / 1.04 / 1.57 deg/s | 1.00 / 1.47 / 2.91 deg/s |

- **交差検証**：ドライブ単位で 5 分割した。a は 40.5〜42.6 m、残差の標準偏差は 0.21〜0.28 deg/s で、組による違いは小さい。
- **見かけのギヤ比**：Kus を無視して δsw / (r/v) を求めると、車速とともに 48 → 76 m と増える。(4.1) によれば、この値は a + b·v² になるはずである。実測はこの形とおおむね合い、アンダーステアの項が効いていることの裏付けになる。
- **外部の値との照合**：opendbc の HONDA_CIVIC（Civic 2016–18）は、L = 2.70 m、SR = 15.38 である。a を 2.70 m で割ると SR = 15.50 で、差は 0.8%。CAN の車速が 1% 大きく出ている分を戻すと 15.35 になる。
- **ホイールベースの扱い**：yaml の L = 2.70 m は仮置きである。この車両の型式は確認できていない。ただし、4.4 の予測は a と b だけで決まり、L を単独で使うことはない。
- **設定の置き場所**：`configs/crosswind/honda_civic.yaml` に置いた。`configs/vehicles/` に置くと、全車種の設定を含む config_hash が変わり、既存のパイプラインが Chunk 3〜10 を「車種の設定あり」として扱うようになるため。

### 4.4 ヨー残差の計算

(4.1) を r について解くと、舵角から期待されるヨーレートが得られる。

    r_pred = v·(δsw − c) / (a + b·v²)                  … (4.2)

これは既存の `features.bicycle_yaw_rate` と同じ式である。ヨー残差は、実測と予測の差とする。

    Δr = r − r_pred                                    … (4.3)

r は 3.2 で作ったジャイロ由来のヨーレートである。Δr が 0 なら、車は舵角どおりに回っている。

## 5. 検証 1：ヨー残差

### 5.1 横風で Δr がどう動くと考えたか

横風を受けながらまっすぐ走ると、風に押されて車が流されたり向きを変えられたりする。運転者はそれを打ち消すため、ハンドルを風上へ少し切ったまま走る。このとき、

- 車は曲がっていないので、実測の r はほぼ 0
- 舵角が δoffset からずれているので、(4.2) の r_pred は 0 でない

となる。したがって、Δr = 0 − r_pred が 0 からずれるはずである。左から風を受けると、運転者は左に切るので r_pred > 0、つまり Δr < 0 になる。

ただし、ずれの大きさは、風の力がかかる点と車の重心などの位置関係で決まる。当て舵がほとんど要らない配置もありうる（5.5）。

### 5.2 直進窓の取り方と窓の値

ドライブを 5 s ごとの窓に区切り、まっすぐ定常に走っている窓だけを残した。

- 条件：
  - 窓の中で常に車速 15 m/s 超
  - r の中央値の絶対値 0.5 deg/s 未満
  - 1 s の移動平均をかけた a_y = v·r の、窓の中の最大と最小の差が 0.5 m/s² 未満
- 窓の数：1,045 個（57 ドライブ、約 87 分）。
- 条件の変更：はじめは、4.2 と同じ「|横躍度| < 0.5」を窓の 90% 以上で満たすこととした。だが、ジャイロから作った横躍度は雑音が大きく、窓が 412 個しか残らなかったので、上の条件に変えた。

窓ごとに、Δr を横加速度の単位に直して平均した。

    y = 窓の中の v·Δr の平均        [m/s²]               … (5.1)

v·Δr は、「舵角から期待される横加速度」と「実際の横加速度」の差にあたる。こう直すと、車速の違う窓どうしを比べやすく、風の力の見積もり（力 / 質量）とも同じ単位で並べられる。

### 5.3 風の横成分

窓の中央の時刻の、SFO の 1 分値（無ければ METAR）を使った。風が吹いてくる方位 D と進路の方位 H の差を θ = D − H とすると、風は進路から見て θ の方向から吹いてくる。θ = −90°（真左）で値が最大になるように、横成分を次のように定義した。

    W_left = −W·sin(D − H)        左から吹くと正、右からなら負       … (5.2)

例：西風（D = 270°）の中を北へ走る（H = 0°）と、W_left = −W·sin 270° = +W で、真左からの風になる。

### 5.4 同じ場所の基準を引く

y には風のほかに、場所に固有の成分も入る。たとえば道路の横断勾配（水はけのための傾き）があると、車は低い側へ流されるので、まっすぐ走るのにやはり当て舵が要る。これを除くため、同じ場所を同じ向きに弱風のときに走った窓を基準にした。

1. 位置を 50 m の升目に、進路の方位を 30° ずつに区切る。その組を「場所」とする。
2. 場所ごとに、弱風（W ≤ 3.1 m/s）の窓の y の中央値を基準 y₀ とする。このとき、自分のドライブの窓は除く。自分自身を基準に含めると、差が 0 に寄るため。
3. 差 Δy = y − y₀ を、W_left に対して直線で回帰する。

       Δy = 定数 + k_y·W_left                            … (5.3)

4. k_y の信頼区間は、ドライブを単位にしたブートストラップ（ドライブを重複を許して選び直す。2,000 回）で求めた。同じドライブの窓どうしは独立でないため。

基準を持つ場所に入った窓は 729 個（55 ドライブ）だった。

### 5.5 結果

| 確認 | 結果 |
|---|---|
| W_left の区分ごとの y の中央値 | どの区分も −0.03〜−0.09 m/s² で、風の向きとの対応がない |
| (5.3) の傾き k_y | −0.0003 m/s² / (m/s)。95% 信頼区間 ±0.003 |
| 突風と、窓の中の Δr・舵角・r の揺れ | 関係がない（順位相関 −0.04〜+0.05）。揺れは車速で決まる（0.67） |
| 1 窓の雑音（弱風の窓の Δy の標準偏差） | 0.05 m/s² |
| 陽性対照：同じ場所の y の再現性 | 場所ごとにドライブを 2 つに分けた組の相関が 0.14。場所ごとの差は 0.037 m/s² 程度 |

表の値は、時刻を丸めた時系列から出したもの。全精度で計算し直した値は 8 章にある（結論は同じ）。

- **効果の上限**：信頼区間の上限で見ても、W_left = 10 m/s での効果は 0.03 m/s² 未満である。これは 1 窓の雑音より小さい。
- **陽性対照**：場所に固有の成分（横断勾配など）もほとんど再現しなかった。この指標は、直進中の小さな当て舵をとらえる感度が低い。
- **見込みの訂正**：検討の途中で「横風による横加速度は約 0.2 m/s²」と見積もった。これは、風の横向きの力を車の質量で割った値である。y に現れるのは当て舵の量で、風の力がかかる点が中立操舵点（舵を切らなくても車が向きを変えない力の作用点）に近ければ、ずっと小さくなる。比べる量を取り違えていたので訂正する。

## 6. 検証 2：横滑り角

### 6.1 横滑り角の計算

横滑り角 β は、車がどちらへ進んでいるか（進路）と、車体がどちらを向いているかの差である。横風で車が横へ流されると、車体は前を向いたまま進路だけが風下へずれるので、β が変わる。当て舵の量ではなく、流され方そのものを見る指標である。

global_pose には、カメラの速度と向きの両方がある。各フレーム（20 Hz）で次のように計算した。

1. **進路の方位**：3.1 と同じく、速度を ENU に回して求める。

       H_v = atan2(v_E, v_N)

2. **車体の方位**：`frame_orientations` のクォータニオン q から回転行列 R(q) を作る（解釈は 6.2）。カメラの前方軸 [1, 0, 0] を ECEF に移し、さらに ENU に回して、東・北の成分 f_E、f_N を取る。

       H_b = atan2(f_E, f_N)

3. **差を取る**：差を −180〜180° に折り返し、左を正にするため符号を反転する。

       β = −( H_v − H_b )                                 … (6.1)

   進路が車体の向きより左にあると、H_v < H_b なので β > 0 になる。

4. **取付の向き**：カメラは車体に対して少し斜めに取り付けられていて、その角度はドライブごとに違う（直進時、つまり v > 15 m/s かつ |r| < 0.5 deg/s のときの β の中央値が −2.0 ± 0.66 deg）。取付の向きは β に一定の値として乗る。
   - 6.3 の陽性対照では、ドライブごとにこの中央値を引いてから使った。
   - 6.4 の当てはめでは、事前には引かず、モデルの「ドライブごとの定数」として吸収させた。
5. **窓の値**：5 章と同じ 1,045 個の直進窓の中で、β を平均した。窓の中に有効な β が 80 個（4 s 分）以上あることを条件にした。

### 6.2 `frame_orientations` の解釈

README には「ECEF からカメラの局所座標 [前, 右, 下] へ回すクォータニオン（Hamilton）」とある。この書き方では、回転行列がどちら向きに作用するのか（カメラ → ECEF か、その逆か）が決まらない。並び順が [w, x, y, z] か [x, y, z, w] かも書かれていない。

そこで 4 通りの解釈を試した。走行中に、カメラの前方軸が速度の向きと揃うのは、「[w, x, y, z] の順で、R(q) がカメラから ECEF への変換」の場合だけだった。この場合の余弦は中央値 0.9994 で、ほかの解釈では 0.17〜0.76 だった。

### 6.3 β が物理的な量か（陽性対照）

姿勢の推定に「車は横に滑らない」という拘束が入っていると、β は横滑りを表さない。そこで、旋回中の β が物理の予想どおりに動くかを確かめた。

**予想の式**：車体の上で、後輪軸から前へ x の位置にある点の横向きの速度は、次の 2 つの和になる。

- 後輪軸そのものの横向きの速度
- 車体が回ることで生じる x·r

後輪軸の横向きの速度は、後輪の横滑り角 α_r を使って −v·α_r と書ける。α_r は、後輪が出す横向きの力、つまり横加速度にほぼ比例する（α_r = k·a_y）。この点の横滑り角は「横向きの速度 / v」なので、

    β ≈ x·(r / v) − k·a_y                               … (6.2)

- **x·(r/v)（幾何の項）**：車体が回っているだけで生じる。タイヤが全く滑らなくても出る。
- **k·a_y（たわみの項）**：タイヤが横に滑る分。本物の横滑りを示すのはこちらである。

a_y = v·r なので、(6.2) は β ≈ (x − k·v²)·(r/v) とも書ける。つまり、車速ごとに β を r/v に回帰した傾き（見かけの x）は、v² に比例して下がるはずである。

**結果**：

| 項目 | 結果 |
|---|---|
| 見かけの x | 車速 8 m/s で 1.77 m、32 m/s で 0.77 m と、v² に比例して下がった |
| x（v → 0 の値） | 1.9 m。後輪軸からフロントガラスの位置までの距離として妥当 |
| k | 0.086 deg/(m/s²) |
| 直進時の雑音 | 20 Hz の標本で 0.12 deg。5 s 窓の中で 0.05 deg |

たわみの項が出ているので、β は横滑りを含んでいる。ただし k は、Civic の大まかな諸元からの見込み（0.15〜0.3 deg/(m/s²)）の 1/2〜1/3 しかない。

見込みの出し方：k = 後輪の荷重 / 後輪のコーナリングパワー（タイヤの横滑り角あたりの横力）とし、後輪の荷重を約 540 kg、コーナリングパワーを 115〜170 kN/rad と置いた。

**姿勢の推定の中で横滑りが弱められている可能性があるが、確かではない。**

### 6.4 横風との関係

**窓の β を何が決めているか**：直進窓の β の平均には、次の 3 つが重なっていると考えた。

    β_窓 = m_ドライブ + s_場所 + k_β·W_left + 雑音          … (6.3)

| 項 | 何を表すか | なぜこの形か |
|---|---|---|
| m_ドライブ | カメラの取付の向き（6.1 の手順 4） | 端末の取付はドライブの中では変わらないので、ドライブごとに 1 つの定数 |
| s_場所 | 道路の横断勾配など、場所に固有の流され方 | 同じ場所を同じ向きに走れば同じだけ流されるので、場所（50 m の升目 × 30° の向き）ごとに 1 つの定数 |
| k_β·W_left | 横風で流される分 | 下で説明 |

**なぜ W_left に比例とみてよいか**：風が車に及ぼす横向きの力は、車に対する空気の相対速度の 2 乗と、空気の当たる角度で決まる。風速 W が車速 v より十分小さいと、相対速度は ほぼ v、空気の当たる角度はほぼ W_left / v になる。そのため、横向きの力はおおよそ v·W_left に比例する。

まっすぐ走っているときは、この力をタイヤの横向きの力が打ち消す。タイヤの横向きの力は横滑り角に比例するので、横滑り角も v·W_left に比例する。車速の範囲が狭ければ、W_left に比例するとみてよい。

v·W_left を説明変数にした当てはめも行ったが、結論は同じだった。左から風を受けると、車体は前を向いたまま進路が右（風下）へずれるので、k_β < 0 が予想される。

**当てはめ方**：(6.3) を、ドライブと場所をそれぞれ 0/1 の目印の変数にした最小二乗で解いた。こうすると、k_β は「同じドライブの中、同じ場所の中で、W_left が違うときに β がどう違うか」だけから決まる。取付の向きや横断勾配が W_left とたまたま相関していても、k_β には混ざらない。

場所の項を入れないモデルも並べた。信頼区間は、ドライブ単位のブートストラップ（500 回）で求めた。

**結果**：

| モデル | k_β [deg/(m/s)] | 95% 信頼区間 | 残りのばらつき |
|---|---|---|---|
| ドライブの定数のみ | +0.003 | −0.0001〜+0.005 | 0.10 deg |
| ドライブ + 場所の定数 | +0.003 | −0.010〜+0.012 | 0.07 deg |

表の値は、時刻を丸めた時系列から出したもの。全精度で計算し直した値は 8 章にある（結論は同じ）。

予想は負だったが、点推定は正で、0 と区別できない。ドライブの定数だけのモデルは横断勾配の影響を除けないので、場所の定数まで入れたモデルのほうが信頼できる。2% の勾配があれば、重力の横成分は約 0.2 m/s² になる。

**期待される大きさ（粗い見積もり）**：
1. SFO で 10 m/s の風は、車の高さでは 6〜7 m/s になるとする。
2. 車速 30 m/s のとき、横向きの力は約 450 N。そのうち後輪が受け持つ分による横滑りは約 0.09°。
3. 6.3 のとおり β が 1/2〜1/3 に弱められているとすると、観測にかかるのは 0.03〜0.04°。風 1 m/s あたりでは k_β ≈ −0.004 deg。

この値は、場所の定数を入れたモデルの信頼区間の中に入る。つまり、今のデータでは、効果があってもなくても区別できない。見積もりは、空気力の係数、風の高さによる弱まり、コーナリングパワーを仮定したもので、数倍は外れうる。

## 7. 追加解析：イベント単位の探索

5 章と 6 章は、横風と横外乱の平均的な関係を見るものだった。ここでは、自動運転モデルの追加学習に使える「強風ヒヤリハット候補」が 1 件でもあるかを、個々の事象として探した。

### 7.1 何を探したか

左から突風を受けたときは、次の順に動くと考えた。

1. 風の力は車の重心より前にかかるので、車首が風下（右）へ振られる。r が舵角から予測される値より右回りに出るので、Δr < 0 になる。
2. 進路も風下へ流されるので、β < 0 になる。
3. 運転者は風上（左）へ当て舵をするので、舵角が増える。

右からの突風では、すべての符号が逆になる。そこで、W_left の符号 s = sign(W_left) を掛けて、「風向と整合する外乱」が正になるようにそろえた。

### 7.2 計算

8 章の全精度の時系列（20 Hz）を使った。

1. **1 秒の移動平均**：v·Δr と β（ドライブごとの取付の向きを引いた後）に、1 秒の移動平均をかける。
2. **場所の基準を引く**：同じ 50 m 升目・同じ 30° の向きを、別のドライブが弱風（W ≤ 3.1 m/s）のときに走った標本の中央値を引く。基準が無い場所では引かない。
3. **z 値にする**：弱風時（車速 15 m/s 超、|r| と |r_pred| が 3 deg/s 未満）のロバストな σ で割り、符号をそろえる。σ は v·Δr で 0.071 m/s²、β で 0.092 deg だった。

       z_r = −s·(v·Δr の 1 s 平均 − 場所の基準) / 0.071
       z_b = −s·(β の 1 s 平均 − 場所の基準) / 0.092

4. **イベント**：z_r と z_b の小さいほう（両方が大きいことを求める）が、しきい値を超える山とした。3 秒以内の山は 1 つにまとめた。
5. **山ごとに記録した量**：
   - 山の前後 1 秒の z_r と z_b の最大値と、その時刻のずれ
   - 山の後 2 秒の、風上への当て舵の大きさ（山の 0.5 秒前の舵角を基準）
   - 山の前 2 秒の操舵：運転者が自分から切った動きかどうかを見るため
   - 前後 3 秒の横への移動量：進路の向きから直線（カーブで一定に曲がる分）を除き、残りを積分した横ずれの幅。車線変更なら約 3.5 m になる

**対象の時間帯**：強風は、その分の突風が 12.5 m/s 以上の時間帯とした。風は 1 分ごとに SFO の値を割り当てた。

**対照**：同じ検出器を次の時間帯にもかけた。
- 強風の時間帯で、s を逆にした場合（風向と逆向きの外乱）
- 弱風の時間帯（s = +1 と −1 の両方）
- 同じ強風のドライブで、突風が 12.5 m/s 未満の時間帯。道路は同じで、風だけが弱い

**探した条件は 2 通り**：
- **1 回目**：山の時刻に |r| と |r_pred| が 3 deg/s 未満。z ≥ 3。
- **2 回目（ほぼ直線の道路だけ）**：山の前後 3 秒の間ずっと |r| と |r_pred| が 1 deg/s 未満。拾い漏らしを避けるため z ≥ 2.5 とした。

### 7.3 結果

**1 回目**

| 区分 | 時間 | 件数 | 1 時間あたり |
|---|---|---|---|
| 強風・風向と整合 | 0.69 h | 3 | 4.4 |
| 強風・風向と逆 | 0.69 h | 5 | 7.3 |
| 同じ強風ドライブの、突風の弱い時間帯（整合／逆） | 1.72 h | 5 / 2 | 2.9 / 1.2 |
| 弱風（s = +1 ／ −1） | 2.1 h | 4 / 6 | 1.9 / 2.8 |

- 強風の時間帯は、どちらの向きでもイベントが多い。強風の 8 件に対し、同じドライブの突風の弱い時間帯の率からの期待は 2.8 件で、偶然でこれ以上になる確率は 0.8% である。
- ただし、8 件のうち 3 件は 06-09 の seg 30 という 1 つのセグメントに集中していて、ここには場所の基準も無い。これを除くと 5 件で、確率は 15% になる。
- 風向と整合する件数（3 件）は、逆の件数（5 件）より多くない。一定の横風に当て舵で耐えている最中に風が弱まれば、車は風上へ動く。そのため、逆向きの山も風が原因になりうる。とはいえ、風向に特有の増え方は見られなかった。

時系列を見ると、どれも突風の形ではなかった。図は `out/crosswind/civic_gust_events/plots/` にある。

山の時刻にだけ旋回の条件を課していたので、前後が旋回中でも拾っていた。

**2 回目（ほぼ直線の道路だけ）**

- 直線で強風だった時間は、約 15 分しかない。
- 風向と整合する 2 件は、弱風の率からの期待（0.33 件）より多く、偶然でこれ以上になる確率は 4% である。しかし、2 件とも中身は突風の形ではなかった。

### 7.4 なぜ見つからないか

- **ふつうの突風は、ばらつきに埋もれる**：1 秒平均の β の雑音は 0.09 deg である。一方、6.4 の粗い見積もりでは、突風による横滑りは 0.03〜0.1° 程度。z ≥ 3 になるには 0.28° 程度の横滑りが要る。今のデータで拾えるのは、見積もりの数倍の、まれに強い外乱だけである。
- **強風で直線を走った時間が少ない**：約 15 分しかない。
- **場所の基準の段差**：50 m の升目の境目で基準が切り替わると、β と Δr に段差ができる。誤検出の原因になっていた。進路に沿ってなめらかにつなぐ基準にすれば段差は消えるが、新しい信号が現れるわけではない。

## 8. 訂正：時刻の丸め

20 Hz の時系列（`out/crosswind/civic_bicycle_fit/grid_20hz.csv.gz`）を書き出すとき、すべての列を有効数字 6 桁（`%.6g`）に丸めていた。

**何が起きたか**：時刻 t は boot time で数万〜百万秒を超える。そのため、389 セグメントのうち 158 が 0.1 秒、143 が 1 秒、3 が 10 秒の刻みに潰れていた。強風のドライブでは、113 セグメントが 1 秒の刻みだった。

**どの処理が影響を受けたか**：
- **受けていない**：ジャイロのずれの推定、横躍度、単軌道モデルの当てはめの本体。書き出す前のメモリ上で計算していたため。
- **受けた**：CSV を読み直して時刻を使った処理。
  - 停車区間との照合
  - 窓の区切りと、位置・速度の補間（`windows.py`）。ただし、風の突き合わせはメモリ上の時刻で行っていた
  - β を時刻に合わせる補間（`beta.py`）
  - 窓の β の取り出し（`beta_wind.py`）

**やり直し**：書き出しを `%.12g` に変え、同じスクリプトで一通り計算し直した（`out/crosswind/civic_v2/`）。既存の出力は、そのまま残してある。

## 9. 限界

- **風の代表性**：風は 10 km 離れた SFO の、高さ 10 m での 2 分平均の値である。全体の 28% の窓は、毎時の METAR で埋めた。
- **量**：強風の直進窓は 10 ドライブに限られる。comma2k19 の強風の時間帯は、すでに全部使っている。
- **β の感度**：β が姿勢の推定で弱められているかどうかは、未確定である。
- **ヨーレート**：ヨーレートは IMU から取り、ずれを推定して引いたもの。推定の誤差（σ 0.06 deg/s）と、ドライブごとの残差の中央値の揺れ（σ 0.11 deg/s）が残る。
- **イベント単位の検出の感度**：1 秒平均の β の雑音は 0.09 deg で、ふつうの突風の見積もり（0.03〜0.1°）より大きい（7.4）。
- **場所の基準**：50 m の升目ごとの定数なので、升目の境目で段差ができる（7.4）。

## 10. 次の候補

- 横風の検討は、comma2k19 ではここで区切る。
- 検証には、車に風速計の付いたデータか、強風の時間帯が多いデータセットを探す。
- 横方向の外乱の検出（二段の設計の 1 段目）は、別の外乱（路面、追い越し車両など）の検証に転用できる。
