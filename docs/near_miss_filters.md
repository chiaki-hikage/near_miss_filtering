# ヒヤリハット候補の検出条件

> **暫定。確定仕様ではない。**
> 閾値は Chunk_1 (RAV4 / 188 セグメント = 約 3.1 時間) の分布から分位点で置いただけで、
> 正解ラベルによる較正はしていない。precision も recall も測れていない状態。
> 実際の値は [`configs/detection.yaml`](../configs/detection.yaml) が正で、
> 本書はその意図と根拠を説明するもの。食い違ったら設定側を見ること。

## 1. 共通の前処理

検出はすべて、一様グリッドへ載せた特徴量に対して行う。

| 段階 | 内容 | 設定 |
|---|---|---|
| 連結 | 同一ドライブの連番セグメントを時間軸で結合 | — |
| 再サンプル | 一様グリッドへ載せる | `resample.rate_hz: 20.0` |
| 欠測 | 受信間隔がこれを超えた区間は NaN のまま | `resample.max_gap_s: 0.5` |
| 端の除去 | 平滑化の端の影響を捨てる | `resample.edge_trim_s: 0.6` |
| 平滑化 | 車速 / 舵角 / 加速度 | `0.25 / 0.15 / 0.25 s` |

生の受信時刻で微分すると量子化ノイズが 100 m/s² 規模に増幅されるため、
再サンプルは省略できない。詳細は [comma2k19_data.md](comma2k19_data.md) 4.2。

平滑化はこれ以上強めていない。加速度の窓を 0.5 秒に広げれば躍度は素直になるが、
短い事象の検出力が落ちる。**躍度のノイズは平滑化ではなく、判定の組み立て方
(3 章・4 章) で扱う。**

**NaN では発火しない。** 欠測は「条件を満たさなかった」ではなく
「判定できなかった」として扱う。

### データセットに依らないこと

3 章以降の条件は、どのデータセットのどの車種かを知らない。
CAN ID とビット定義は車種設定 (`configs/vehicles/*.yaml`)、
データセット固有の読み出しは `src/near_miss/io/` にだけある。

| 決めること | 置き場所 |
|---|---|
| どのファイルをどう読むか | `io/comma2k19.py` / `io/comma_car_segments.py` |
| どの CAN ID の何ビット目か | `configs/vehicles/*.yaml` |
| どの特徴量をどの閾値で見るか | `configs/detection.yaml` |

このため、車種が変わっても検出条件は書き換えない。実際に
comma2k19 の RAV4 (2017) と commaCarSegments の RAV4 TSS2 では
ブレーキのアドレス・レーダのアドレス・加速度計の符号が違うが、
違いはすべて車種設定に収まっている
([comma_car_segments.md](comma_car_segments.md) 5 章)。

**解析窓は主系列 (車速・舵角・ヨーレート) の重なりで決める。**
付随信号は車種や年式で有無が変わり、受信の始まりも数十 ms ずれる。
そこへ窓を合わせると、信号を 1 本足しただけで検出結果が動いてしまう。
グリッド点も boot time の 1/20 秒の倍数に固定してあり、
区間の端が少し動いてもサンプル位置はずれない。

## 2. 特徴量

### 判定に使うもの

| 特徴量 | 定義 | 元の信号 |
|---|---|---|
| `v_mps` | 平滑化した車速 | `speed` (processed) |
| `ax_mps2` | `v_mps` の微分 → 平滑化 | 同上 |
| `steer_rate_dps` | 平滑化した舵角の微分 | `steering_angle` (processed) |
| `steer_reversals` | 10 秒窓での符号反転回数 | 同上 |
| `ay_kin_mps2` | `v_mps × yaw_rate` → 平滑化 | raw_can 0x024 + `speed` |
| `ay_can_mps2` | 符号補正した `ACCEL_Y` | raw_can 0x024 |
| `net_heading_win_deg` | 前後 3.0 秒の正味方位角変化の絶対値 | raw_can 0x024 |
| `weave_active` | 左右交互の急な操作を検出した区間 (0/1) | 上記 + `steering_angle` |
| `cut_in_active` | 割り込みを検出した区間 (0/1) | `radar` + `speed` |
| `thw_s` | `lead_distance_m / v_mps` | `radar` (processed) |
| `ttc_s` | `lead_distance_m / (-lead_vrel_mps)` | 同上 |
| `fabs` | ABS 作動フラグ | raw_can 0x320 |
| `lc_active` | S 字状の横運動を検出した区間 (0/1) | raw_can 0x024 + `speed` |

**縦加速度の主系列は `ax_mps2` (車速の微分)。** `ACCEL_X` はスケールファクタの
妥当性が未確定なので、`ax_can_mps2` として並置し差を `ax_residual_mps2` に残すだけ。

**横加速度の主系列は `ay_kin_mps2` (車速 × ヨーレート)。** `YAW_RATE` のスケールは
`global_pose` を基準に検証済み (回帰係数 0.988) で単位が確かなのに対し、
`ACCEL_Y` は路面カントの寄与とスケール誤差を分離できず未確定のため。

### 補助特徴量 (判定には使わない)

候補行に添えて、確認時の材料にする。

| 特徴量 | 定義 | 位置づけ |
|---|---|---|
| `jerk_mps3` | `ax_mps2` の微分 | 生値。ノイズが多い |
| `jerk_win_min` / `jerk_win_mean` | 上を 0.3 秒窓で最小 / 平均 | 制動の急峻さの目安 |
| `lat_jerk_mps3` | `ay_kin_mps2` の微分 | 生値 |
| `lat_jerk_win_absmax` | 上の絶対値を 0.3 秒窓で最大 | 操舵の急峻さの目安 |
| `ws_spread_mps` | 4 輪速の最大 − 最小 | スリップの手がかり |
| `lc_offset_m` | 車線変更候補の推定横変位 (正が左) | 1 車線ぶんかの確認 |
| `lead_track_id` | 先行車のレーダトラック ID | 入れ替わりの確認 |
| `cut_in_distance_drop_m` | 割り込みで縮んだ車間 | 割り込みの大きさ |
| `cut_in_thw_after_s` | 割り込み後の車間時間 | 同上 |
| `weave_reversals` | 蛇行と判定した区間の振れ回数 | 蛇行の中身 |
| `steer_reversals` | 舵角の符号反転回数 (旧定義) | 参考 |
| `lc_heading_amp_deg` | 同じく方位角の振りの大きさ | 同上 |
| `ax_can_mps2` / `ax_residual_mps2` | `ACCEL_X` と主系列との差 | 整合の点検 |
| `yaw_rate_dps` / `steer_deg_s` | 生の回転・舵角 | 挙動の確認 |
| `op_tx` | openpilot の制御フレーム送信 | 全区間 1 に張り付き機能していない |

窓長は `auxiliary.window_s: 0.3`。

### 先行車の選び方

レーダのトラックから、各グリッド点の先行車を 1 つ選ぶ。条件は 3 つ。

| 条件 | 値 | 理由 |
|---|---|---|
| 自車進路からの横ずれ | 1.8 m 以内 | 自車レーンにいること |
| 距離 | 1.0〜150.0 m | レーダの有効範囲 |
| **先行車の絶対速度** | **2.0 m/s かつ自車速の 0.2 倍を超える** | **静止物を外す** |

満たすもののうち**最も近いもの**を先行車とする。観測が途切れた区間は
直近値を 0.5 秒まで保持し、それ以上は欠測にする。

#### 静止物を外す

路側の標識・ガードレール・停車車両は相対速度が −自車速 になるため、
`TTC = 距離 / 自車速` となって恒常的に小さい値を出す。しかも近いので、
実在の先行車より優先して選ばれてしまう。

Chunk_1 で発火した `low_ttc` 25 件は**すべてこれだった**。

```
                 先行車の絶対速度 (自車速 + 相対速度)
low_ttc   25 件   中央値 -0.13 m/s   範囲 [-9.55, 0.43]   ← 静止物、一部は対向
short_thw 17 件   中央値 29.36 m/s   範囲 [12.94, 34.69]  ← 実在の先行車
```

絶対速度で足切りすると `low_ttc` は 0 件になり、`short_thw` は 17 件すべて残る。
**誤検出だけが落ちる。**

`low_ttc` が 0 件になるのは指標が無意味だからではない。openpilot の ACC が
車間を維持しており、3.1 時間のあいだ実際に接近する事象が無かったと解釈する。

#### 進路の曲がりに合わせて帯をずらす

レーダは車両固定座標で報告するので、正面に取った帯は直進を仮定している。
旋回中はその帯が路側を掃く。自車のヨーレートから曲率 `κ = ヨーレート / 車速` を
出し、円弧の近似 `y = κ x² / 2` で進路のずれを求めて帯を曲げる。
低速 (3.0 m/s 未満) では曲率が発散するので補正しない。

旋回中 (|ヨーレート| > 3 deg/s、車速 5 m/s 超) のレーダ観測 67,630 点で確認した。

| 補正 | 帯に入る静止物 | 帯に入る移動物 | 移動/静止 |
|---|---|---|---|
| なし | 4,267 | 11,534 | 2.70 |
| **+κx²/2** | **381** | **17,394** | **45.65** |
| −κx²/2 | 2,260 | 8,004 | 3.54 |

静止物が 91% 減り、実在の先行車が 51% 増える。符号もこの比較で確かめた。

### 車間指標

- `thw_s` と `ttc_s` は `v_mps >= 5.0 m/s` のときだけ算出する
- `ttc_s` はさらに相対速度が負 (接近) のときだけ定義する。離れていく先行車に TTC は無い

自車が止まっている間に TTC を出さないのは、停止中に相対速度が負になるのが
「相手がこちらへ近づいている」状態であって自車側のヒヤリハットではないため。

## 3. 検出条件

`op` は `lt` = 未満 / `gt` = 超過 / `abs_gt` = 絶対値が超過 / `rising` = 0→1 の
立ち上がり / `agreement` = 複数信号がそろって条件を満たす /
`cooccurrence` = 別のイベントに危険側の指標が重なる。
`stage 2` は `raw_can` の復号が要るもの。

| イベント | 判定量 | op | 暫定閾値 | 最短継続 | ゲート | 重み |
|---|---|---|---|---|---|---|
| `hard_brake` 急ブレーキ | `ax_mps2` | lt | −2.5 m/s² | 0.3 s | — | 1.0 |
| `hard_accel` 急加速 | `ax_mps2` | gt | +2.5 m/s² | 0.3 s | — | 0.4 |
| `hard_steer` 急操舵 | 3 信号の整合 (下記) | agreement | — | 0.15 s | `正味方位角 < 15 deg`, `v > 5 m/s` | 0.3 |
| `lateral_accel` 横加速度過大 | `ay_kin_mps2` | abs_gt | 3.0 m/s² | 0.2 s | `正味方位角 < 15 deg`, `v > 5 m/s` | 0.3 |
| `weaving` 蛇行 | `weave_active` | gt | 0.5 | 0.5 s | — | 0.5 |
| `short_thw` 車間時間過小 | `thw_s` | lt | 0.6 s | 0.5 s | — | 1.0 |
| `low_ttc` 衝突余裕時間過小 | `ttc_s` | lt | 2.0 s | 0.3 s | — | 1.5 |
| `cut_in_candidate` 割り込み | `cut_in_active` | gt | 0.5 | 0.3 s | — | 1.5 |
| `lane_change_candidate` 車線変更の候補 | `lc_active` | gt | 0.5 | 0.5 s | — | 0.2 |
| `risky_lane_change` 危険な車線変更の疑い | 共起 (下記) | cooccurrence | 1 種以上 | — | — | 2.0 |
| `abs_active` ABS 作動 | `fabs` | rising | — | — | — | 2.0 |

閾値は Chunk_1 実測の分位点に合わせてある。

| 判定量 | p99 | p99.9 | 最大 | 採用閾値 |
|---|---|---|---|---|
| `ax_mps2` (下側) | — | −2.69 (p0.1) | −4.44 | −2.5 |
| `\|ay_kin_mps2\|` | 2.19 | 3.58 | 4.89 | 3.0 |
| `ttc_s` (下側) | — | 1.09 (p0.1) | 0.38 | 2.0 |

### 判定ロジック

閾値系のイベントは共通で 3 段。

1. 条件を満たすサンプルの連続区間を取る
2. 間隔が `merge_gap_s` (既定 1.0 s、蛇行のみ 2.0 s) 以内の区間をひとつにまとめる
3. まとめた後の継続時間が最短継続に届かないものを捨てる

2 を挟むのは、閾値付近で条件が細切れになるのを防ぐため。

**ゲート**は「その条件が成り立つ区間だけ判定する」足切り。挙動の意味が変わる
速度域を除くために使う。必要な列が無いときはゲートを無視せず、判定そのものを
行わない。発火した条件は `events.csv` の `gate` 列に残る。

### 急操舵 — 3 信号の整合で判定する

ひとつの信号の閾値超過は、ノイズなのか実際の挙動なのか区別できない。
独立した 3 系統がそろって立っていることを条件にする。

| 条件 | センサ | 意味 | 閾値 |
|---|---|---|---|
| `\|steer_rate_dps\|` | 舵角センサ | 運転者の入力 | 25.0 deg/s |
| `\|ay_kin_mps2\|` | ヨーレートセンサ × 車速 | 車両の応答 | 2.0 m/s² |
| `\|ay_can_mps2\|` | 横加速度センサ | 独立した実測 | 1.4 m/s² |

各条件のマスクを `tolerance_s: 0.3` だけ前後に広げてから連言を取る。
別々のセンサが同じ挙動を捉える時刻には必ずずれがあるため、厳密な同時刻を
要求すると実在する事象を取り逃がす。**広げるのは各条件の側だけで、連言そのものは
緩めない。1 系統だけの単発スパイクは他が裏付けないので通らない。**

`ay_can` の閾値 1.4 は `ay_kin` 側の 0.68 倍。横加速度計は路面カントのぶんだけ
小さく読み、実測の回帰係数が 0.678 だったことによる。ここでは大きさの根拠ではなく
裏取りに使うだけなので、スケール未確定でも差し支えない。

3 条件の連言は Chunk_1 全サンプルの 0.12% にあたる。

#### ヨーレートを生の大きさで使わない理由

`ay = 車速 × ヨーレート` なので、ヨーレートに固定の下限を置くと、
**高速ほど大きな横加速度を要求してしまう。**

| 車速 | `\|yaw\| > 12 deg/s` が要求する横加速度 |
|---|---|
| 50 km/h | 2.91 m/s² |
| 100 km/h | 5.82 m/s² |
| 120 km/h | 6.98 m/s² |

Chunk_1 の `|ay_kin|` 最大は 4.89 m/s²、90 km/h 超でのヨーレート最大は 10.42 deg/s。
実際、ヨーレートに 12 deg/s を課した版は **90 km/h 超での発火率が 0.0%** だった。
ヒヤリハットが最も問題になる速度域を丸ごと落とすため、車速を掛けた形で使う。

### 割り込み — 先行車が入れ替わって車間が詰まること

目視判定でリスクとされた車間逼迫は、**いずれも他車が前方に割り込んだ場面**だった。
車間時間の絶対値より、割り込みで急に詰まったことが危険の中身にあたる。

主判定は**距離の不連続**。実在の車両は 1 サンプル (0.05 秒) で数十 m も動けないので、
先行車の距離が跳ぶことは別の物体に替わったことを意味する。

| 条件 | 値 |
|---|---|
| 1 サンプルでの距離の跳び | 5.0 m 以上縮む |
| 入れ替わり前後の車間の差 | 10.0 m 以上縮む |
| 入れ替わった先の車間時間 | 0.8 秒以下 |
| 先行車がいなかった場合の出現距離 | 40.0 m 以内 |
| 自車速 | 8.0 m/s 以上 |
| 持続 | 0.8 秒 |

**トラック ID の変化は補助にとどめる。** レーダはトラックの枠を使い回しており、
同じ車両を追っていても ID が頻繁に入れ替わる (実測で 14 秒間に 28〜92 回)。
ID が一定であることを条件にした最初の実装では、既知の割り込みが 1 件も取れなかった。

車間時間の上限 0.8 秒は、既知の割り込み 4 件が 0.23〜0.51 秒だったことによる。
1.8 秒では 26 件/時と多すぎ、0.8 秒で 10 件/時になる。

### 車線変更 — 候補として拾い、危険側と重なったときだけ格上げする

**comma2k19 に車線マーカの正解が無いため、車線変更と断定はできない。**
「1 車線ぶんに相当する横変位を伴い、方位角が元へ戻る左右一組の振り」という
運動の形だけで拾い、名前も `candidate` に留める。

手順は次のとおり (設定は `lane_change` 節)。

1. ヨーレートから道路の曲率成分を引く (窓 10.0 秒の**中央値フィルタ**)
2. 残った偏差が ±0.6 deg/s を超えて振れている区間を「ローブ」として取り出す
3. 隣接する逆符号のローブ 2 つを一組として評価する
4. 次をすべて満たすものを候補とする

| 条件 | 値 | 意味 |
|---|---|---|
| 各ローブの方位角変化 | 1.5 deg 以上 | 振りの大きさ |
| ローブ間の間隔 | 3.0 秒以内 | 一連の動作であること |
| 一組の長さ | 1.0〜8.0 秒 | 車線変更の時間スケール |
| 正味の方位角変化 | 2.5 deg 以内 | **元の向きに戻ること** |
| 推定横変位 | 2.0〜6.0 m | **1 車線ぶん** (目安 3.5 m) |
| 車速 | 10.0 m/s 以上 | 低速の切り返しを除く |

横変位は相対方位角を積分して `∫ 車速 × sin(方位角) dt` で求める。

#### 曲率の推定に移動平均を使ってはいけない

ヨーレートが段状に変わるカーブの出入りでは、移動平均が前後になまされ、
偏差に**左右一組の振れが出る**。これは車線変更の S 字と区別できず、
カーブ 1 つにつき出入りで 2 件の誤検出になる。中央値フィルタは段差を
そのまま保つのでこの振れが出ない。カーブ中の車線変更も、曲率と切り分けて拾える。

#### 危険側との共起

車線変更そのものは日常的な操作なので、重みは 0.2 と低く置く。
危険側の指標が**前後 2.0 秒以内に 1 種類以上**重なったときだけ
`risky_lane_change` を立て、重み 2.0 を与える。

対象は `low_ttc` / `short_thw` / `hard_steer` / `lateral_accel` / `hard_brake` /
`abs_active`。ESC・TCS は `ESP_CONTROL` のビット定義が未取得のため入れられない。

区間は車線変更のものをそのまま使う。確認するのはその操作だからで、
重なった指標の側へ広げると何を見ればよいのか分からなくなる。

### 個別の注意

**`hard_brake`** — 映像確認で妥当と判断されたため、閾値を −3.0 から −2.5 に
緩めて候補を増やした。Chunk_1 での検出数は次のとおり。

```
-3.0 :  5 件   -2.8 :  7 件   -2.5 : 11 件   -2.2 : 21 件   -2.0 : 32 件
```

**`hard_brake` / `hard_accel`** — 勾配補正をしていない。280 号線には ±3 度程度の
勾配があり、`ax_mps2` は車速の微分なので勾配の影響を受けない一方、
`ax_can_mps2` は重力成分を含む。両者の差が `ax_residual_mps2` に出る。

**`weaving`** — 舵角の符号反転を数えるだけの旧定義は、通常の複数車線変更を
蛇行として拾っていた (目視判定 6 件がすべて通常運転で、コメントも
「蛇行ではないが右に 2 レーン分車線変更している」だった)。次の 3 点を加えた。

| 条件 | 値 | 意味 |
|---|---|---|
| 左右交互の振れの回数 | 3 回以上 | 一方向の車線変更ではない |
| 各振れの横加速度 | 1.0 m/s² 以上 | 車両が実際に応答している |
| 各振れの舵角レート | 8.0 deg/s 以上 | 運転者が実際に操作している |
| 振れの間隔 | 2.0 秒以内 | 短時間に集中している |
| 全体の長さ | 2.0〜8.0 秒 | 同上 |
| 正味の方位角変化 | 8.0 deg 以内 | **元の向きへ戻る** |
| 車速 | 10.0 m/s 以上 | — |

道路の曲率は車線変更と同じく中央値フィルタ (窓 10.0 秒) で除く。
この定義で、蛇行と判定されていた 9 件すべてから蛇行イベントが消えた。

**`hard_steer` / `lateral_accel` に旋回除外のゲートを掛けてある。**
前後 3.0 秒の正味方位角が 15.0 deg を超える区間は判定しない。左折・ランプ・
長いカーブは向きが変わり続けるので大きな値になり、回避操作や車線変更は
元の向きへ戻るので小さい。目視判定では、通常の旋回 6 件が除外され、
リスクと判定された 2 件 (割り込みへの反応、車線変更の中止) は残った。

**重みも 0.8 から 0.3 に下げてある。**
上位の候補を映像で確認したところ、通常のカーブ走行やバイパスへ進入するための
左折だった。候補には残すが、単独では上位に来ないようにしている。
`ay_kin_mps2` はスケール検証済みなので閾値 3.0 m/s² (約 0.3 G) は物理量として
読めるが、高速道路の曲線や出口ランプでもこの値に達する。

**`short_thw` / `low_ttc`** — 高速道路では本命の指標。ただし先行車の選択が
横位置しきい値だけの割り切りなので、曲線区間では隣接レーンの車両を拾いうる。
曲率補正は未実装。

**`abs_active`** — ABS の作動は危険挙動の直接証拠なので重み 2.0 を与えている。
ただし **Chunk_1 では作動しえない状況しか無かった** (最大減速度 0.45 g、
タイヤ限界の半分)。定義の正しさはこのデータでは確かめられない。

車両側の減速フラグ (`decel_flag`) は別に取れており、`ax_mps2` を裏付ける
文脈量として候補行に添えてある。ABS ではないのでイベントにはしていない。

## 4. 複合パターンと車両物理

単独の閾値超過は、危険かどうかを決めきれない。並びや組み合わせ、
車両の応答が物理から外れているかを見る。

### 設計の整理

| パターン | 必要な信号 | 特徴量 | 物理的な判定条件 | 現データで検証できるか |
|---|---|---|---|---|
| アクセル急 OFF → 制動 | (アクセル開度) / `speed` | `panic_brake_active` | 縦加速度が正から −3.0 m/s² 以下へ 1.5 秒以内 | **代用のみ。**アクセル開度のビット定義が未取得で、加速度で代用している |
| ↑ に前方要因が伴うもの | + `radar` | `panic_brake_with_lead` | 上に車間逼迫・割り込み・急接近が ±2 秒で重なる | ○ (検出 0 件) |
| S 字回避 | `steering_angle` + `YAW_RATE` + `speed` | `s_evasion_active` | 横変位が 1.2 m 以上ふくらみ、最後に 1.0 m 以内へ戻る | ○ (検出 0 件) |
| 制動＋操舵の回避 | 上記 + `speed` | `brake_and_steer` | 急制動と急操舵/回避が ±1 秒で重なる | ○ (検出 0 件) |
| 回避後の制動 | 同上 | `brake_after_evasion` | 回避/急操舵の 0〜3 秒後に急制動 | ○ (検出 0 件) |
| 割り込み | `radar` + `speed` | `cut_in_active` | 先行車の距離が不連続に縮み、車間時間が 0.8 秒以下になる | ○ (33 件) |
| 急接近 | `radar` + `speed` | `closing_fast_active` | 同じ先行車のまま車間時間が -0.4 s/s より速く縮む | ○ (3 件) |
| リスクを伴う車線変更 | 上記すべて | `risky_lane_change` | 車線変更に危険側の指標が ±2 秒で重なる | ○ (3 件) |
| ヨー応答の乖離 | `steering_angle` + `YAW_RATE` + `speed` | `yaw_residual_sigma` | 単軌道モデルの予測から 6σ 以上外れる | ○ (1 件) |
| 逆操舵 | 同上 | `counter_steer_active` | 旋回中に逆向きへ舵を切る | **単独では不可。**下記 |
| 輪速の不整合によるスリップ | `wheel_speed` + ABS/ESC/TCS | `ws_spread_mps` | 駆動・制動で説明できない輪速差 | **不可。**ESC/TCS のビット定義が未取得 |
| ABS 介入 | `VSC1S07` | `fabs` | 作動フラグの立ち上がり | **検証不可。**最大減速度 0.45 g でタイヤ限界に遠く、作動しえない |
| ESC / TCS 介入 | `ESP_CONTROL` / `VSC1S08` | — | 作動フラグ | **不可。**64 ビットすべて固定値で中身が無い |
| 強い減速 (車両側) | `VSC1S07` | `decel_flag` | 減速度の閾値で立つ (50% 点が約 −2.4 m/s²) | ○ 挙動は検証済み。`ax_mps2` の裏付けに使える |

### 車両物理モデル

線形単軌道モデルで、舵角から期待されるヨーレートを出す。

```
r_expected = v · δsw / (SR · (L + Kus · v²))
```

係数は車種設定の `geometry` に持たせてあり、実測で求めた
(SR = 16.75、Kus = 0.00235、ゼロ点 +0.911 deg、R² = 0.973)。
根拠は [signals_rav4.md](signals_rav4.md)。

`yaw_residual_sigma` は実測との差を残差の標準偏差 (0.341 deg/s) で
割った値。閾値を σ 単位で置けるようにしてある。

**閾値 6σ は保守的に置いてある。** 定常状態のモデルなので操舵の立ち上がりでは
必ず差が出る (|残差| > 1.5 deg/s の点は |横躍度| の中央値が全体の 6 倍)。
過渡を誤検出しないよう、継続時間 0.3 秒と併せて絞っている。

### 逆操舵を単独のイベントにしていない理由

旋回中に逆向きへ舵を切る操作は、滑りの立て直しでも起きるが、
**カーブや車線変更の終わりでは必ず起きる**。通常の操作と区別できない。

Chunk_1 で単独イベントとして出したときは 25 件のうち 11 件が単独候補となり、
車速の中央値は 26 km/h、目視判定との対応も取れず、上位 10 位の適合率が
71% から 57% へ下がった。特徴量 (`counter_steer_active`) としては残し、
制動との共起 (`brake_and_steer`) の材料にとどめている。

### 検出 0 件をどう読むか

`s_evasion` / `brake_and_steer` / `brake_after_evasion` /
`panic_brake_with_lead` は Chunk_1 で 1 件も出ていない。

これは定義が働いていないという意味ではなく、**この 3.1 時間に
回避操作が起きなかった**と読むのが妥当。openpilot の ACC と LKA が
動いている高速道路の通勤で、車両は一貫して線形領域にあり
(残差の標準偏差 0.341 deg/s)、ABS も 1 度も作動していない。

件数を作るために閾値を緩めると、通常の操作を拾って上位を埋めることは
`counter_steer` で確認済み。**0 件のまま残し、他のチャンクや別の
データセットで確かめる。**

## 5. 単独では判定しないもの

### 制動ジャーク — イベントから外した

`jerk_mps3` は微分 2 回でノイズが乗る。Chunk_1 全体での 1 サンプルごとの
符号反転率は次のとおりで、物理的な躍度ではなく量子化ノイズが支配的。

```
jerk_mps3      符号反転率 23.9%   閾値 -4.0 の超過 0.023%
lat_jerk_mps3  符号反転率 14.2%   閾値 +4.0 の超過 0.090%
ax_mps2        符号反転率  3.9%   閾値 -3.0 の超過 0.046%
```

最短継続を変えたときの検出数を見ると、閾値超過が持続的な現象として
存在しないことが分かる。

```
最短継続 0.00s : 19 件
最短継続 0.05s : 11 件
最短継続 0.15s :  5 件   ← 以前の設定
最短継続 0.30s :  0 件
```

**継続時間でノイズを削っていただけで、制動ジャークを検出できていなかった。**
イベント定義から外し、縦方向の急変は `hard_brake` (`ax_mps2`) を主判定とする。
躍度は `jerk_win_min` / `jerk_win_mean` として候補行に添えるに留める。

`lat_jerk_mps3` も同じ理由で単独判定に使わない。急操舵は 3 章の 3 信号整合で見る。

### スリップ — 定義していない

`ws_spread_mps` (4 輪速の最大 − 最小) は加減速時に駆動・制動で正常にも開く。
**これ単独ではスリップと判定できない。** 縦加速度・ヨー/操舵・ABS/TCS/ESC の
作動と整合を取る前提だが、`ESP_CONTROL` (0x3B7) のビット定義が未取得で
TCS/ESC の作動を読めない。読めるようになるまでイベントとして定義せず、
候補行の文脈量として添えるに留める。

## 6. 未実装

### VSC / TC の介入

**ビット定義を入手したが、介入フラグは存在しなかった。**
opendbc の `ESP_CONTROL` (0x3B7) にあるのは `TC_DISABLED` / `VSC_DISABLED` /
`BRAKE_HOLD_ACTIVE` で、いずれも「無効化されているか」であって
「介入したか」ではない。RAV4 2017 と TSS2 のどちらの DBC でも同じだった。
comma2k19 側では 0x3B7 の 64 ビットが全て固定値でもあり、二重に確認できない。

`risky_lane_change` の共起条件に VSC / TC 介入を加える案は、
この車種では実現できない。

### ABS 作動

`FABS` (0x320 bit 2) は両データセットで復号できるが、
comma2k19 の 3.1 時間でも commaCarSegments の 3.3 時間でも一度も立たなかった。
comma2k19 では最大減速度が 0.45 g で、タイヤ限界 (乾燥路 0.8〜1.0 g) に届いておらず、
強制動中の前後輪速度差も通常走行時より小さい。**作動しうる走行が含まれていない。**

`abs_active` の定義自体は残してあるが、**現時点で検証されていない**。
降雨・降雪路やより強い制動を含むデータが要る。
`scripts/screen_segments.py` は、この信号を復号できたセグメントの割合と最大値を
必ず出すので、規模を上げても 0 のままかどうかは結果に残る。

### 純正 AEB (PCS)

TSS2 では `PRE_COLLISION` (0x283, バス 2) の `PRECOLLISION_ACTIVE` を復号できる。
作動していれば車両自身が危険と判断した直接の証拠になる。
`aeb_active` として定義したが、196 セグメント (3.3 時間) で作動 0 件、
制動要求 `FORCE` [N] も全区間 0 だった。**定義は未検証のまま。**

### 輪速の異常

`wheel_speed_anomaly` を定義した。旋回で説明できる量 (ヨーレート × トレッド幅) を
差し引き、区間ごとの中央値も引いたうえで、加減速・ヨー応答の乖離・ABS の
いずれかで裏付けが取れた区間だけを拾う。

ただし **生の輪速はそのままでは使えない**。1 サンプルごとの符号反転率が
62〜67% (白色雑音なら 50%) で、高周波ノイズが支配的だった。
平滑化前の実装では comma2k19 で 16 件出たが、中身は隣り合うサンプルで
ばらつきが 0.04 → 0.70 → 0.09 と飛び跳ねているだけで、持続していなかった。
0.3 秒平滑化すると超過の最大が 1.31 → 0.27 m/s に落ちる。

平滑化後は comma2k19 (3.1 時間) でも TSS2 (3.3 時間) でも 0 件。
超過の最大は 0.42 m/s で、この信号品質では
「輪速の異常は無い」と言えるところまでは確かめられた。

### アクセル急 OFF からの制動 (ペダル判定)

`panic_brake_pedal` を定義した。縦加速度で代用していた `panic_brake` と違い、
「踏んでいた → 離した → 短時間でブレーキと強い減速」という運転者の動作を見る。

`0x2C1 GAS_PEDAL` の復号率は TSS2 で **34.7%** しかない
(車両によってメッセージ自体が流れていない)。台数を増やしてもこの車種の
3 分の 1 しかカバーできないため、縦加速度で代用する `panic_brake` も残してある。
検出は comma2k19 で 2 件、TSS2 の 196 セグメントで 1 件。

### 逆操舵

`counter_steer` をイベントとして出すようにした。
以前は特徴量にとどめていた (Chunk_1 で 25 件のうち 11 件が単独候補になり、
車速中央 26 km/h で目視判定とも対応しなかった)。
通常の旋回・車線変更の終わりの舵戻しを除くため、
`hard_steer` と同じ gate (車速 > 10 m/s かつ正味方位変化 < 15 deg) を付けてある。
これで comma2k19 は 25 → 8 件、TSS2 の 196 セグメントで 4 件。
重みは 0.3 に置き、単独では上位に来ないようにしている。

## 7. 候補区間の統合とスコア

個々のイベントは短いので、前後 2.0 秒を付けたうえで 2.0 秒以内のものを
ひとつの候補区間にまとめる。

```
イベント単体のスコア = 重み × min(1 + 超過量 / |閾値|, 3.0)
候補区間のスコア     = 種類ごとの最大スコアの合計 + 0.5 × (種類数 − 1)
```

閾値ちょうどで 1.0 になる。同じ種類が複数あっても最も強い 1 件だけを足す。
異なる種類が重なったときに加点するのは、**単独の閾値超過より共起のほうが
ヒヤリハットらしい**という前提による。この前提自体もまだ検証していない。

`agreement` のイベントは、代表値 (`feature` が指すもの) の超過量でスコアを出す。

スコアは順位付けの目安であって、危険度の絶対尺度ではない。

## 9. 確認と較正の進め方

`scripts/make_review_list.py` が確認シート (`review.md` / `review.csv`) を出す。
セグメント内の相対秒とフレーム番号、映像の場所が入っているので、そのまま
頭出しできる。判定欄に **ヒヤリハット / 通常運転 / 判断不能** を記入したものを
正解として閾値を較正する。

`scripts/plot_segment.py` は 1 セグメントの時系列を出す。検出に使う特徴量は
すべてパネルとして選べ、閾値・発火区間・ゲートで判定対象外になった区間を重ねる。
候補が出なかった理由が、閾値未達なのか対象外だったのかを切り分けられる。

残っている課題。

1. **`cut_in_candidate` の目視確認。** 33 件のうち判定済みは 4 件だけ。
   残りが実際に割り込みかを確かめないと、閾値 (車間時間 0.8 秒) の妥当性が分からない。
   上位 10 件のうち 8 件が割り込みを含むので、ここの精度が全体を決める
2. **制動系の重み付け。** リスクと判定された制動 2 件が割り込みに押されて
   34 位・36 位まで下がった。深さだけでは危険度が決まらないことも分かっており
   (−3.06 は通常、−3.29 はリスク、−3.60 は通常)、文脈を伴う指標が要る
3. **`lateral_accel` が 0 件になったことの確認。** 旋回除外で全滅したので、
   イベントとして残す意味があるか判断する
4. `op_tx` を作動判別に置き換える (現状は全区間で 1 に張り付き機能していない)
5. `ESP_CONTROL` のビット定義を取得し、スリップと VSC/TC 介入を定義する
6. アクセル開度のビット定義を取得する。`panic_brake` は加速度で代用しており、
   「踏んでいた足を離した」ことを直接は見ていない
