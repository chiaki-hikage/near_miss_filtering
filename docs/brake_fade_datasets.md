# ブレーキフェードの候補抽出: データセットの適合性 (2026-11-18)

検出の方針: 下り坂に限らない。直前の反復制動・継続制動で熱負荷がたまったあとに、
**同じくらいの制動の要求に対して減速度が下がっている**場面を拾う。

この文書はデータセットの適合性の確認と、最小限の PoC の提案まで。
データの取得・既存のコードと環境の変更は、まだしていない。

## 1. 区別する 4 つの事象

| 事象 | 何で分かるか | 必要な信号 |
|---|---|---|
| 反復制動・継続制動 | 制動の回数・時間・失った運動エネルギー。運転のしかたの話で、性能の低下は含まない | 車速、ブレーキの on/off |
| 制動性能の低下 | 要求 (油圧・ペダル量) あたりの減速度が、同じ車の平常時より下がる | 油圧かペダル量の**連続値**、縦加速度か車速 |
| 熱によるフェード | 性能の低下 + 直前の熱負荷が高い + 冷えると戻る。ほかの原因 (路面の濡れ・勾配・積載・タイヤ・ABS・計測の誤り) を除いたもの | 上の 2 つ + 温度か熱負荷の推定、勾配、ABS |
| ヒヤリハット | 周りとの関係 (前の車・歩行者) で危険が生じた場面。フェードが原因になりうるが同じではない | 前方の映像・レーダー |

制動性能の低下は、熱以外の原因でも起きる。ブレーキの温度が無いデータでは、
「熱によるフェード」は**推定の候補**までで、確定はできない。

## 3. 既存の ZOD・comma2k19 で確かめたこと

### ZOD (手元の vehicle_data、50 シーケンスの信号の一覧)

- ブレーキに関する信号は `brake_pedal_pressed` (0/1) とその品質の列だけ。油圧・ペダル量・輪速・ABS・温度は無い
- ほかに使えるのは、アクセルの開度 (0〜100)、縦の速度・加速度、ピッチ角、衛星測位の高度
- 走行全体 85 走行・92 時間を一時スクリプトで走査した (結果は保存していない)
  - 制動している時間の割合: 中央値 6%
  - 60 s の間に制動中に失った運動エネルギー (質量あたり) の最大: 走行ごとの最大の中央値 250 J/kg、全体の最大 563 J/kg。100 km/h からの 1 回の停止 (約 390 J/kg) と同じ程度
  - 120 s の間の最大の下り: 中央値 42 m、最大 146 m
- 結論: 熱負荷が高い場面がほとんど無い。ブレーキの要求の大きさも取れないので、「要求あたりの減速度」を計算できない

### comma2k19

- RAV4 と Civic の詳しい比較は 6 章。要点:
  - **RAV4 (Chunk 1〜2) にも、制動の連続値が流れていた。** 0x224 (バス 0) の byte4〜5 で、opendbc の `BRAKE_PRESSURE` の位置 (start 43、12 bit) とずれていたため、これまで復号できていなかった
  - Civic (Chunk 3〜10) には `USER_BRAKE` (0x1A4) と `BRAKE_PRESSURE1/2` (0x1E7) がある。本プロジェクトでは Civic の CAN を復号していなかった
  - どちらも単位は不明で、相対値として使う。I-280 の高速道路の通勤が主で、制動が少なく、フェードはまず含まれない。使いどころは、利きの推定のばらつき (検出の下限) を測る**平常の基準**

## 4. 適合性の判断

| データセット | 判断 | 理由 |
|---|---|---|
| Toyota GR Cup | **第一候補だが、今は使えない** | 信号 (前後の油圧・加速度・車速・舵角・位置・周回距離) と熱負荷の高さは一番合う。毎周同じコーナーで比べられる。ただし利用条件がハッカソン限りで、配布先も 404。TRD の許可が要る。温度・ABS・映像は無い |
| NCST 重量車 | **熱負荷の推定の検証に使う** | CC0・17 MB で、油圧と温度が同じ記録にある唯一のデータ。ただし 1 Hz・1 台・加速度なし・温度の抜けと過小評価。フェードは含まない見込み |
| comma2k19 (RAV4・Civic) | **手法の土台と平常の基準に使う** | 取得済み。両車とも制動の連続値があり、減速度とほぼ直線の関係 (6 章)。映像と同期できる。熱負荷は低い |
| ZOD | **使いどころは少ない** | ブレーキが on/off だけで要求あたりの減速度を出せない。熱負荷の高い場面も少ない |

4 つのどれにも、フェードの事象のラベルは無い。熱によるフェードを確かめられるのは、
温度と油圧と加速度がそろったデータだけで、今のところ該当するものが無い。

## 5. 最小限の PoC の提案

目的: 「熱負荷の推定」と「要求あたりの減速度 (制動の利き) の推定」の 2 つを作り、
それぞれがどこまで信用できるかを、手元のデータと小さなデータで先に確かめる。
GR Cup の許可が取れたら、同じ処理をそのまま当てる。

| 段階 | データ | すること | 取得 |
|---|---|---|---|
| 1 | comma2k19 RAV4 (取得済み。Civic で確かめ直す) | 0x224 byte4〜5 の復号の追認 (`global_pose` の勾配で補正、openpilot の自動ブレーキの区間を分ける)。制動ごとの「利き」= 減速度 ÷ 要求 を求め、平常時のばらつきを測る (どれだけ下がれば検出できるか)。同じ処理を Civic の `BRAKE_PRESSURE1` に当てて比べる | なし |
| 2 | NCST (17 MB、CC0) | 車速と油圧から作る熱負荷の推定 (失った運動エネルギーの和 − 冷却、1 次の遅れ) を、測った温度と比べる。報告書の 2.3×10⁻⁵ °C/J と合うか、冷却の時定数はいくつかを見る | **17 MB (要確認)** |
| 3 | 1・2 の結果 | 「熱負荷が高い」かつ「利きが平常より下がった」制動を候補にする規則を書く。反復制動だけ・性能の低下だけ・両方 (フェードの疑い) の 3 つに分けて出す | なし |
| 保留 | GR Cup | TRD に社内研究での利用の許可を問い合わせる。許可が出れば、同じコーナーの制動を周ごとに比べる (油圧あたりの減速度の周ごとの変化) | 許可しだい |

段階 1 で制動の連続値の意味が確かめられないときは、段階 3 は
「熱負荷の推定」だけの PoC に縮める。

## 6. comma2k19 の RAV4 と Civic の比較 (2026-11-18 追記)

手元の全データで調べた。RAV4 は Chunk 1〜2 の 382 セグメント (6.0 時間、走行中で使えた分)、Civic は 389 セグメント (6.2 時間)。新しい取得はしていない。
調べ方:
1. 生 CAN の全アドレスを数えた (RAV4 169 個、Civic 89 個)。
2. opendbc の DBC (RAV4 は Toyota 2017 系の 5 ファイル、Civic は Civic 2016 Touring と共通の 3 ファイル) と突き合わせた。
3. DBC に頼らず、全メッセージの全バイトと 16 bit の組を、ブレーキの on/off と輪速の微分から作った減速度に突き合わせた (総当たり)。
一時スクリプトは作業用のフォルダにあり、結果は `out/` に保存していない。

### 6.1 区別の書き方

- **ある**: 値が流れていて、振る舞いを確かめた
- **ある・復号できていなかった**: 値は流れているが、DBC の位置が違うなどで、これまで読めていなかった
- **枠だけ**: メッセージは流れているが、記録中に値が一度も変わらない (作動が無かったのか、中身が無いのかは区別できない)
- **記録に無い**: 記録したバスにメッセージが無い (車にあるかどうかは分からない)
- **DBC に無い**: メッセージは流れているが、該当する信号の定義が無く、総当たりでも見つからない

### 6.2 信号の一覧

| 項目 | RAV4 (2017、ガソリン) | Civic (2016、ガソリン) |
|---|---|---|
| ペダルの on/off | **ある** (0x224 bit 5、41.4 Hz。検証済み) | **ある** (0x17C `BRAKE_PRESSED`、100 Hz) |
| 運転者の踏み込みの大きさ | 下の油圧と同じ信号 (運転者の操作にだけ反応する) | **ある** (0x1A4 `USER_BRAKE`、49.9 Hz)。openpilot の自動ブレーキでは動かない |
| 油圧 | **ある・復号できていなかった** (0x224 byte4〜5、41.4 Hz)。opendbc の `BRAKE_PRESSURE` (start 43、12 bit) は位置が違い、256 の倍数しか出ない。既存の文書 (signals_rav4.md 2 章) の「byte5 はカウンタ」は誤り。byte5 は踏み始めから滑らかに増える値だった | **ある** (0x1E7 `BRAKE_PRESSURE1/2`、49.9 Hz)。運転者の踏み込みと openpilot の自動ブレーキの**両方**で上がる |
| 油圧の実測値 (MPa) | **記録に無い。** DBC (toyota_2017_ref_pt) の 0x226 VSC1F06 `PMC` (MPa) は、バス 0 に無い。バス 1 の 0x226 はレーダーの 0x210〜0x232 の並びの一部で、制動と関係しない (相関 0.26 以下) | **DBC に無い** |
| 要求制動力 (自動ブレーキの指令) | openpilot の `ACC_CONTROL` (0x343、src 128) の `ACCEL_CMD` (m/s²)。走行中の 4.7% の時間で −0.3 m/s² より強い減速の指令 | openpilot の `BRAKE_COMMAND` (0x1FA、src 128) と、車からの `COMPUTER_BRAKING` (0x1A4)。どちらも走行中の 9.0% の時間で立つ |
| ABS の作動 | **記録に無い** (作動フラグは 0x226 にあるはずで、上と同じ)。`FABS` (0x320) は故障フラグ | **DBC に無い** |
| VSC・TRC | 0x3B7 は**枠だけ** (64 bit すべて固定)。0x226 の `VSCACT` は記録に無い | 0x1A4 の `ESP_DISABLED` (スイッチの状態) |
| その他の制動の状態 | 0x320 `DECEL_FLAG` (強い減速で立つ、意味は未確定)、`PCSBRSTA`・`BRTYPACC` などは DBC にあるが未検証。0x0BA `FHACHOLD` (坂道発進の保持) | 0x1A4 `BRAKE_HOLD_*`、0x1B0 `WHEELS_MOVING` |
| 回生ブレーキ | **無い** (ガソリン車。ハイブリッド用の 0x127 が無く、ガソリン車の 0x3BC がある) | **無い** (ガソリン車) |
| 縦加速度 (車両) | `GVC` (0x320、20.7 Hz、0.04 m/s² 刻み)。輪速の微分と r 0.98・傾き 0.95 | `LONG_ACCEL` (0x1EA、49.9 Hz、約 0.1 m/s² 刻み)。r 0.97・傾き 0.91。前回 (3 章) の「ビット位置が疑わしい」は誤りで、刻みが粗いだけ |
| 勾配 | `ASLP` (0x320、1 deg 刻み、実勾配と r 0.76)、`global_pose` | `global_pose` |

ABS・VSC は、両車とも検証できない。どちらのデータでも減速度は p0.1 で −2.7〜−2.9 m/s² までで、タイヤの限界に遠く、作動しうる場面が無い。

### 6.3 制動の連続値と縦加速度の対応

> **2026-11-18 追記:** この表の「減速度との相関」と「10 分位ごとの直線性 (R²)」は別の計算 (前者は 20 Hz の時刻ごと、後者は 10 分位の平均 10 点どうし) で、
> 時刻ごとの単回帰の R² は RAV4 で 0.75。勾配を補正した正常制動の模型と、学習に使っていない走行での精度は [brake_performance_rav4.md](brake_performance_rav4.md)。
> 「利きのばらつき 約 30%」は勾配の補正なしの値で、global_pose で補正すると約 11% になった。

走行中 (3 m/s 超) で、ペダルを踏んでいる間に限って比べた。減速度は輪速の微分で、勾配は補正していない。

| | RAV4 0x224 byte4〜5 | Civic `USER_BRAKE` | Civic `BRAKE_PRESSURE1` |
|---|---|---|---|
| 周期 | 41.4 Hz | 49.9 Hz | 49.9 Hz |
| 分解能 | 1 (整数) | 0.015625 | 0.015625 |
| 踏んでいないとき | 0〜5 (多くは 0〜2) | 約 0 | 約 −101.4 |
| 踏んでいる間の p99 | 188 | 1.67 | −99.7 |
| 減速度との相関 | −0.87 | −0.90 | −0.90 |
| 10 分位ごとの直線性 (R²) | 0.999 | 0.993 | 0.990 |
| 遅れ (この分解能 0.05 s で) | 0 s | 0.05 s | 0 s |
| 踏まずに減速 (−0.7 m/s² より強い) しているとき値が上がる割合 | 0.01% | 0.3% | 87% (自動ブレーキ中は 99%、それ以外は 4%) |
| 停止中に踏み続けたときの値 (中央値) | 94 | 0.67 | −100.7 |
| 単位 | **不明** (DBC は位置も違う) | **不明** (DBC に係数はあるが単位は空欄) | **不明** (同上。原点 −103 の意味も不明) |
| 2 s 以上の制動 (走行中、減速 0.5 m/s² 超) | 78 回 | 71 回 | 72 回 |
| 制動ごとの利き (減速度 ÷ 値) のばらつき (四分位から求めた変動係数) | 0.30 | 0.31 | 0.34 |
| 利きの p10・p90 (中央値との比) | 0.72・1.73 | 0.80・1.51 | 0.79・1.55 |

- 3 つとも、踏んでいない間はほぼ動かず、踏むと減速度と直線の関係になる。加速度センサではなく、制動の要求か油圧を表している
- RAV4 の値は、openpilot の自動ブレーキ中 (指令 −0.5 m/s² より強い、減速の中央値 −0.85 m/s²) には 5 を超えない。運転者側の油圧 (マスターシリンダ) とみられる。自動ブレーキは別の経路で圧をかけていて、この信号には出ない (推定)
- Civic の `BRAKE_PRESSURE1/2` は、自動ブレーキでも上がる (自動ブレーキ中の減速度との相関 −0.87)。実際にかかっている油圧に近いとみられる (推定)
- 利きのばらつきは、勾配を補正していない今の段階で約 30%。この大きさでは、1 回の制動で 30% 程度の低下を見分けられない。勾配の補正と、同じ速度・同じ強さの制動どうしの比較で、どこまで下がるかが段階 1 の主な課題

### 6.4 PoC に使う車両の提案

**RAV4 を主に使い、Civic で確かめ直す。**

| 観点 | RAV4 | Civic |
|---|---|---|
| データの量 | Chunk 1〜2 がすべて手元にある (6.0 時間) | 手元は 389 セグメント (6.2 時間) で、Civic の全体の一部 |
| 制動の連続値 | 1 つ。きれいな 0 点 (踏まないと 0〜5)、直線性が一番よい | 2 つ (運転者の踏み込みと油圧) あり、互いに突き合わせられる |
| 自動ブレーキ | 油圧に出ない。指令 (`ACCEL_CMD`) で区間を見分けて、利きの計算から外す | 油圧に出る。自動ブレーキの制動も利きの計算に使える (回数が増える) |
| 縦加速度・勾配 | `GVC` 0.04 m/s² 刻み、`ASLP` もある | `LONG_ACCEL` は 0.1 m/s² 刻みで粗い |
| 本プロジェクトの土台 | 復号の設定 (`configs/vehicles/toyota_rav4.yaml`) と検証の記録がある | Civic の CAN の復号は未実装 |

- RAV4 を主にする理由は 3 つ。データが全部そろっていること、0 点がはっきりして直線性が一番よいこと、`GVC`・`ASLP` など減速度と勾配の手がかりが多く、既存の復号の土台があること
- Civic は、油圧が自動ブレーキも含めて取れる点で RAV4 より有利。RAV4 で作った利きの推定を Civic の `BRAKE_PRESSURE1` に当て、車が違っても同じように働くかを確かめる
- どちらの単位も分からないので、利きは**同じ車の平常時との比**でだけ使う。車どうしで利きの値を比べない
- 熱負荷の推定は油圧を使わず、車速から求める (制動中に失った運動エネルギー)。RAV4 で油圧に出ない自動ブレーキの制動も、熱負荷には入れる

既存のコード・設定・文書 (RAV4 の `BRAKE_PRESSURE` を `enabled: false` にした設定と、signals_rav4.md 2 章の記述) は変えていない。0x224 byte4〜5 を設定に足すか、記述を直すかは、ユーザーの判断を待つ。
