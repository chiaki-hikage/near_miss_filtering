# 週次報告スライドの作成

プロジェクト関係者・管理者に、進捗・主な実験結果・課題・次週の予定を説明するスライドを作る。
この skill は使いながら直していく。直したら末尾の「改訂の記録」に書く。

## 守ること

- **PPT を作る時期はユーザーが決める。** ユーザーが頼んだときだけ作る。原稿や構成案を整えたついでに作らない
- **構成案に合意を得てから PPT を作る。** 構成案を示した回答では PPT を作らない。合意の返事が来てから作る
- 毎週 **5〜7 枚**。ユーザーが枚数を指定したらそれに従う (`limits` だけを変えた設定の写しを `--config` で渡す)
- 各スライドは **タイトル / 主文 1 つ / 図か表 1 つ + 注釈**。**1 スライド 1 メッセージ**
  - 主文は、そのスライドで言いたいことを 1 文で言い切る (結論を先に)。言いたいことが 2 つあるなら 2 枚に分ける
  - 図表は主文を裏付けるものを 1 つだけ選ぶ。注釈には読み方・条件・限界を書く
- 確かさを超えて書かない。`experiments/index.csv` の `verification`・`decision` を超えた言い方 (検証済み・採用済み) をしない。予定は「(案)」と書く
- 根拠のパスを各スライドに付ける。`out/` の結果は索引に行があるものを挙げる

## 作成方針 (毎回共通。2026-11-13 にユーザーが指定)

- **1 スライド 1 メッセージ**を徹底する
- **主文は結論を表す 1 文で、原則 1 行に収める** (4:3・16 pt で全角 40 字程度まで)
- 文字量を抑え、図・イラスト・グラフを積極的に使う。表より、主文を一目で裏付ける図を優先する
- 詳細な条件・仮定・不確かさは、注釈・脚注・補足資料に回す
- **実際の解析結果や画像を優先し、推測の数値や架空の結果は使わない**。図の数値は結果ファイルから読んで描く (手で書き写さない)
- 確定していないことを確定したように書かない。「整合を確認」と「原因と確定」は区別する
- スライド間のストーリーと、見た目 (色・記号・図の描き方) の一貫性を重視する
- ユーザーが示した構成案は叩き台。情報量・見せ方・文言は、方針に沿って改善してよい (変えたところは伝える)

## 手順

### 1. 材料を集める (ファイルは書き換えない)

| 材料 | 場所 |
|---|---|
| 原稿 (その週の作業・結果・課題・予定) | `reports/weekly/<YYYY-Www>/notes.md` (無ければ `reports/weekly/TEMPLATE.md` から作り、中身をユーザーと確かめる) |
| 前回報告からの変更点 | `uv run python scripts/report/weekly_changes.py <notes.md>` → `changes.md` |
| テーマごとの状況 | `docs/roadmap.md` |
| 結果の状態 (利用・検証・採否・食い違い) | `experiments/index.csv` (`attention` 列) |
| 図の候補 | `shared/`、索引の `shared_copies` 列、各解析フォルダの図 |
| 前回の構成案 | `reports/weekly/<前の週>/outline.yaml` |

### 2. 構成案を作り、ユーザーに示す

1. `reports/weekly/OUTLINE_TEMPLATE.yaml` を写して `reports/weekly/<YYYY-Www>/outline.yaml` を書く
2. `uv run --extra report python scripts/report/build_weekly_pptx.py <outline.yaml> --check` で検査する (枚数・主文・図表の数・ファイルの有無。PPT は作らない)
3. 構成案を次の表で示し、**合意を求めて止まる**

| 枚 | タイトル | 主文 (1 文) | 図・表 | 注釈 | 根拠 |
|---|---|---|---|---|---|

あわせて、次を短く添える。
- 全体の流れ (何をどの順で伝えるか) と、そう組んだ理由
- 入れなかった話題とその理由
- 迷った点 (主文の言い切りの強さ、図の選び方など)

構成を吟味するときの観点:
- 1 枚目で今週の結論が分かるか。最後まで読まなくても要点が伝わる順か
- 各スライドの主文だけを順に読んで、話がつながるか
- 主文と図表が合っているか (図表が主文を裏付けているか)
- 同じことを 2 枚で言っていないか。1 枚に 2 つのことを言っていないか
- 数字に単位と条件があるか。確かさの言い方が根拠と合っているか

### 3. 合意を得たら PPT を作る

```bash
uv run --extra report python scripts/report/build_weekly_pptx.py reports/weekly/<YYYY-Www>/outline.yaml
```

- 出力は `reports/weekly/<YYYY-Www>/weekly_<YYYY-Www>.pptx` (git 管理外) と `changes.md`
- 見た目を確かめる。手元に PowerPoint・LibreOffice が無いときは、1 枚ずつのファイルに分けて macOS の Quick Look (`qlmanage -t -s 1600`) で描く。文字のはみ出し・重なり・図の縮みを見る
- 直したら、直したことをユーザーに伝える。構成 (主文・図表) を変えるときは、もう一度合意を取る

### 4. 記録する

- `outline.yaml`・`notes.md`・`changes.md` は git 管理。コミットはユーザーが頼んだときだけ
- `docs/roadmap.md` の状況と「最終更新」を直す
- AI 活用の事例があれば `reports/ca/cases.md` に足す

## 体裁

- 体裁の設定 (色・文字の大きさ・配置・上限) は `configs/report_weekly.yaml`。社内テンプレートが見つかっていないので暫定テンプレート。毎回共通 (2026-11-13 にユーザーが指定):
  - **4:3** (10 × 7.5 in)
  - 字体は **Yu Gothic UI** (図は近いものとして游ゴシック `YuGothic`)
  - **タイトルの前に太い縦棒**。タイトルと主文の間の横棒は入れない
  - **主文は「■」の箇条書きの形**
  - 色は**紺・青・水色のブルー系が基調**。**強調するところだけ赤・オレンジ**を使ってよい。図の色も設定の `theme` の色にそろえる
- 1 枚の配置: 上にヘッダー (週と期間。outline の `header` で変えられる) → 縦棒 + タイトル → ■ 主文 → 図か表 (全幅) → 注釈 (左) と根拠 (右) → ページ番号
- 図は全幅の枠 (約 9.0 × 3.9 in) に合わせて作る。縦長の図・表は `layout: right` で注釈を右に置く
- 図の中の枠 (パネル) を使うときは、文字・図形が枠の内側に収まっていることを描いた後に確かめる (例: `scripts/report/crosswind_slides_figs.py` の `inside_check`)
